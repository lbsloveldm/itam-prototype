## 2. 需求分析

### 2.1 业务背景

资产盘点是对组织内资产进行物理检查与记录的关键过程，用于保证准确性、完整性、合规性、安全性、成本控制、责任分配与风险管理。盘点任务由执行者/协作者完成并提交后，需要由**任务创建人**对结果进行复核：确认账实差异、处理新增/缺失资产，最终将复核确认的结果同步回资产台账，形成闭环。

### 2.2 需求价值

#### 2.2.1 模块价值点

参考 ServiceNow 资产盘点（Audit）关注的清单准确性、生命周期管理、内部控制与合规性。复核环节的核心价值在于「让盘点差异有人负责确认」——通过复核人把关，避免盘点执行者的误判直接写入台账，同时保证真实差异被及时更新到台账并留痕。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow：盘点差异分类统计与图形化展示、复核确认后更新配置/资产记录。本系统在 DCIM 已有页面基础上，增加五类结果的图形化占比展示、异常明细逐条复核、复核后台账三类更新（改属性/新增/置 丢失）并记录 Activity。

### 2.3 用户故事

#### 2.3.1 盘点对象

- 库房中的资产 —— 在库盘点；其他地点（办公室或数据中心）—— 在用盘点。

#### 2.3.2 角色要求

- 角色 资产维护人：**任务创建人**有权复核并提交复核结果，其他用户不可复核。

## 3. 需求设计

### 3.1 涉及到的表

- `audit_task`（盘点任务表）
- `audit_result`（盘点结果/明细表）
- `asset`（资产台账表，复核后更新属性/状态）
- `asset_activity`（资产操作日志表）
- `规格` / `model_category`（规格/类别表，New 明细展示）

### 3.2 查看盘点结果与复核

#### 3.2.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 任务状态显示 | 任务提交后按逾期情况显示「已完成」或「逾期完成」 | 此时用户可查看结果 |
| 复核权限 | 任务创建人有权复核并提交复核结果，其他用户不可复核 | 点击任务名称查看结果，创建任务的 资产 角色拥有复核权限，结果页每条记录可编辑 |
| 图形化占比 | 在 DCIM 已有页面增加图形化展示盘点结果占比 | 展示 A/B/C/D/E 五类占比（见字典值） |
| 盘盈盈亏组合 | 区分找到但值不同，用于满足多种展示：盘亏＝B2+C，盘盈＝B1+D+E | 本期不做值加总统计，后续国产化有需要时再加总 |
| 异常数据详情 | 需包括 B、C、D、E 四种情况 | 点击异常数据数量可进入修改（记录系统当前值、盘点者手动填写的值） |
| 逐条修改 | 在结果页点击资产名称，直接显示该资产盘点时不同的属性值，可直接修改 | 参考 DCIM 修改值交互 |
| 任务间切换 | Next 查看同一盘点计划的下一个任务结果，Preview 查看上一个 | 同属一个盘点计划 |

#### 3.2.2 饼图统计口径（20250307 补充）

| 状态 | 饼图统计数据来源 |

| 任务已提交未复核前 | 以盘点人提交的数据结果进行统计展示 |

#### 3.2.3 字段字典值说明（五类盘点结果）

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 盘点结果分类 | A. Scanned and expected | 找到目标且账实相同 |
| 盘点结果分类 | B1. 耗材 值 Greater than Target | 耗材盘点值大于目标 |
| 盘点结果分类 | B2. 耗材 值 Less than Target | 耗材盘点值小于目标 |
| 盘点结果分类 | B3. 硬件 值 Not Equal to Target | 硬件盘点值不等于目标 |
| 盘点结果分类 | C. Expected and not found | 未找到的目标 |
| 盘点结果分类 | D. Scanned and not expected | 扫到不在本次任务范围内的资产 |
| 盘点结果分类 | E. New | 台账中不存在的新资产 |

### 3.3 New / Scanned and not expected 的复核处理

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 耗材SN 为空 | 当 规格 为 consumable 时 SN 为空 | 点 编辑 进入 耗材 创建页，以草稿对应值填充相应字段，其余字段为空，需复核者填写 |
| New 提交创建 | 点 提交 后该资产被创建成功，完成编辑且该条盘点记录已复核完成 | — |
| New 直接确认 | 直接点 确认 则以任务盘点者提交的字段值成功创建资产，且该条盘点记录被复核完成 | — |

### 3.4 复核确认与台账更新

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 认可结果 | 复核人认可时点 确认，资产台账属性值以执行盘点人提交的为准更新 | — |

| 二次确认 | 点提交复核结果时二次确认，提示语「资产 information will be automatically updated after submission. Please confirm to submit the review results」 | — |

#### 3.4.1 后端处理三件事（确认 / 确认 all / 编辑）

| 场景 | 后端处理逻辑 | 日志 |
| --- | --- | --- |
| a. 属性值不相同 | 从资产管理系统修改确认要修改的资产属性值 | 保留操作日志记录，展示在资产 Activity |
| b. New 新增资产 | 从资产管理系统增加之前不存在的资产 | 保留新增记录，展示在资产 Activity |
| c. 未找到的资产 | 将资产状态 状态 属性值改为 丢失 | 保留更新记录，展示在资产 Activity |

## 4. 验收标准

- 仅任务创建人可复核并提交复核结果，结果页每条记录可编辑；其他用户无复核权限。
- 五类盘点结果（A/B/C/D/E）图形化占比展示正确；异常明细（B/C/D/E）可逐条进入修改并记录系统值与人工填写值。
- 饼图统计口径按「复核前用盘点人数据、复核后用复核人数据」切换。
- 复核确认后台账三类更新（改属性/新增/置 丢失）执行正确并记录到资产 Activity。
- 仅当所有明细处于非编辑态方可提交复核结果，提交有二次确认；提交后可生成并导出盘点报告。
- Next/Preview 可在同一盘点计划内切换任务结果。
