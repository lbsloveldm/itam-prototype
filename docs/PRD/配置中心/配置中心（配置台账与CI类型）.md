## 2. 需求分析

### 2.1 业务背景

截图跨多产品家族部署，ITAM 之外存在配置中心（CMDB）兄弟产品。CMDB 以配置台账统一登记 IT 环境中的配置项（CI）及其类型，是资产与运维数据的底座。ITAM 硬件资产与 CMDB CI 一对一关联，资产的配置/组件、CPU 核数等信息来源于 CI。本模块在同一原型模板中补齐配置中心的核心页面：配置台账（CI 列表/详情）与 CI类型（类型清单）。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **统一配置底座**：集中登记 IT 环境所有配置项，为资产、运维、变更提供一致的数据来源。
- **资产-配置打通**：CI 与 ITAM 资产双向关联，避免同一实体在两套系统中割裂维护。
- **分类可扩展**：以 CI类型的父子层级组织配置项，支持后续按类型扩展专属属性。
- **责属清晰**：负责人 / 归属组织 / 更新人明确配置项责任归属，便于审计与追溯。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow CMDB：配置项按 CI Class 层级化建模（cmdb_ci 基类派生硬件/软件/网络等子类）；CI 与 资产 一对一关联；详情页含身份/管理/状态/网络等多组信息与关系图谱。本原型精简为「身份/管理/状态/网络」四组核心字段，关系以单条 `relatedAsset` 展示（见第 6 节简化说明）。

### 2.3 用户故事

- 作为**CMDB 管理员**，我希望维护 CI类型的父子层级，以便按类型组织配置项。
- 作为**运维人员**，我希望在配置台账登记设备并标注运行状态与负责人，以便快速定位与追责。
- 作为**资产管理员**，我希望在 CI 上看到关联资产，以便核对资产与配置数据一致性。

## 3. 需求设计

### 3.1 配置台账（配置项管理）

#### 3.1.1 涉及到的表

- `cis`（配置项主表，`CiSchema`）
- `ciTypes`（CI类型表，`CiTypeSchema`，被 CI 的 `ciType` 引用）
- `assets`（资产表，通过 `relatedAsset` 弱关联，原型以资产标识文本表达）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 配置项列表 | 展示全部配置项，支持搜索 | 搜索字段为 `名称 / 规格 / owner`；运行状态以彩色 标签 显示（运行中=绿/已下线=橙/已停用=默认） |
| 新建配置项 | 进入详情页新建 CI | 点击「新建」跳转 `/cmdb/ci/new`；保存时 `createdBy` 默认 `demi`，写入 `createdTime/updatedTime` |
| 编辑配置项 | 修改 CI 字段 | 保存时更新 `updatedTime`；详情头部信息条同步刷新 |
| 删除配置项 | 列表/详情删除，二次确认 | 列表行内 Popconfirm「确定删除该配置项？」；详情页亦提供删除 |
| CI类型下拉联动 | 新建/编辑时 CI类型下拉来自 CI类型清单 | 下拉选项 = `ciTypeCollection` 全部类型名称；新建默认「硬件设备」 |
| 关联关系展示 | 详情「关联关系」页签展示关联资产 | 当 `relatedAsset` 非空且非 `-` 时，展示单行（关系类型=关联资产、关系=安装于、目标=资产标识）；否则空态 |

#### 3.1.3 字段说明

字段来源：`cis.ts` 的 `CiSchema`。长度栏中表单未显式限制的以「原型为准」。

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| id | VARCHAR | - | 配置项主键（系统生成，如 `ci1`） |
| 名称 | VARCHAR | 100 | 配置项名称，必填（表单 `maxLength=100`），如「键盘3」 |
| CI类型 | VARCHAR | - | 引用 CI类型名称，必填，下拉选择 |
| 运行状态 | VARCHAR | - | 运行中 / 已下线 / 已停用，必填 |
| 负责人 | VARCHAR | - | 责属人；列表展示（任务补充字段，以原型为准） |
| IP地址 | VARCHAR | - | 网络信息，默认 `-`（任务补充字段，以原型为准） |
| 关联资产 | VARCHAR | - | 关联资产标识，如 `P000000013`（任务补充字段，以原型为准） |
| 配置编码 | VARCHAR | - | 身份信息 |
| 信创标识 | VARCHAR | - | 是否信创设备，如「是」 |
| 型号 | VARCHAR | - | 设备型号，如 `A10AX3200`；列表展示 |
| 所属环境 | VARCHAR | - | 如「生产」 |
| 设备来源 | VARCHAR | - | 管理信息，如「采购」 |
| 采购日期 | VARCHAR | - | 采购日期，格式 `YYYY-MM-DD`（原型为文本输入） |
| 用途类型 | VARCHAR | - | 如「办公」 |
| 归属组织 | VARCHAR | - | 归属组织，默认「集团」 |
| 备注 | VARCHAR | 256 | 多行文本，`maxLength=256`，showCount |
| 创建人/更新人 | VARCHAR | - | 详情头部展示为「更新人」 |
| 创建时间 | TIMESTAMP | - | 创建时间 |
| 更新时间 | TIMESTAMP | - | 更新时间，头部信息条展示 |

#### 3.1.4 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 运行状态 | 运行中 | 正常运行（列表 标签=绿色） |
| 运行状态 | 已下线 | 已下线（列表 标签=橙色） |
| 运行状态 | 已停用 | 已停用（列表 标签=默认灰） |
| CI类型 | 公共 / 硬件设备 / 软件系统 / 网络设备 | 引用 CI类型清单，可维护扩展 |
| 信创标识 | 是 / -（否/未标注） | 是否信创设备，原型为自由文本 |

### 3.3 页面功能与交互逻辑

#### 3.3.1 配置台账列表页（`/cmdb/ci`）

- **默认展示列**：配置项名称（可点击进详情）、CI类型、运行状态（彩色 标签）、负责人、IP、型号、关联资产、操作（删除）。
- **搜索**：按 名称 / 型号 / 负责人（`名称 / 规格 / owner`）模糊搜索。
- **操作**：新建（跳详情）、删除（行内 Popconfirm）。

#### 3.3.2 配置项详情/新建页（`/cmdb/ci/:id`）

- **头部**：标题为 CI 名称 + CI类型蓝色 标签；信息条展示 运行状态 / 归属组织 / 更新时间 / 更新人。
- **页签**：
  - 基本信息：Collapse 分四组——身份信息（名称/CI类型/配置编码/信创标识/型号/所属环境/备注）、管理信息（设备来源/采购日期/用途类型/归属组织/负责人）、状态信息（运行状态/关联资产）、网络信息（IP地址）。
  - 关联关系：展示与 CI 关联的资产（单行）；无关联时展示「暂无关联关系」空态。
- **校验**：名称、CI类型、运行状态必填；备注 ≤256 字符。
- **404 守卫**：访问不存在的 CI ID 展示「未找到该配置项」结果页与「返回配置台账」入口。
- **新建默认值**：CI类型=硬件设备、运行状态=运行中、IP=`-`、归属组织=集团。

#### 3.3.3 CI类型清单页（`/cmdb/ci-type`）

- 列表 + 弹窗 内联新建/编辑/删除，不拆分独立 `/:id` 详情路由（见第 6 节简化说明）。

## 4. 验收标准

- 配置台账可完成新建、查看、编辑、删除全流程，字段与字典值符合本文定义。
- 列表搜索（名称/型号/负责人）与运行状态彩色 标签 正确。
- 详情页头部信息条、四组 Collapse、关联关系页签、404 守卫均生效；新建默认值正确。
- CI类型清单以 弹窗 内联维护，父类型下拉含 `-`（顶级）+ 已有类型，删除有二次确认。

## 6. 简化说明（原型范围）

- **CI 详情字段精简**：真实截图含身份/管理/状态/网络/位置/背板/其他/责属/维保/供应商等约 10 组，本原型精简为身份/管理/状态/网络四组核心字段。
- **CI 关联关系简化**：真实 CMDB 支持复杂关系图谱，本原型仅以 `relatedAsset` 展示单条关联资产。
- **CI类型无独立详情页**：作为小清单以 弹窗 内联维护，未拆分 `/:id` 路由。
