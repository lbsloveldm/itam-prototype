## 2. 需求分析

### 2.1 业务背景

ITAM 操作需填写不同表单或属性才能完成，增加了用户学习成本与操作路径。AI 能力通过自然语言交互，降低操作复杂度，并让分散在 Excel、财务软件、云平台的数据实现「一句话」查询与统计，把资产数据变为经营决策依据。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **操作简化**：以对话替代多步表单，退役、盘点、维护创建从数分钟降至秒级。
- **零培训**：用户无需理解「模板/计划/任务」概念，像聊天一样下达指令。
- **数据透视**：跨维度统计与可视化，随时掌握资产变化趋势与成本浮动。
- **流程贯通**：打通台账、成本、组织数据，实现从查询到工单发起的闭环。

#### 2.2.2 调研结论及竞品分析

对标 ServiceNow Now Assist 等 AI 助手：以自然语言驱动流程与查询。本方案基于 Dify 工作流编排 + 前端 AI 助手，强调查询准确率与召回率的可验收目标。

### 2.3 用户故事

- 作为**资产管理员**，我希望说「北京分公司所有笔记本，让王工每月1号盘一次」即可生成盘点任务，以便免去多步操作。
- 作为**IT 运维**，我希望问「维修成本过高的资产有哪些」并直接发起退役，以便快速处置。
- 作为**管理层**，我希望问「各分公司在库空闲电脑数量」即得图表与结论，以便决策。

## 3. 需求设计

### 3.1 资产退役-操作简化

#### 3.1.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 现状 | 工单填写计划退役时间、选择退役资产 | 可选对象状态为在库及在用，发起退役申请 |
| 痛点 | 无法准确查询待退役设备 | 需通过间接查询记录后再进入退役流程发起 |
| Step1 查询待退役类 | Query 待退役设备 | 支持「待退役（可退役）的设备有哪些、已到达退役时间的设备有哪些、维修成本过高的资产有哪些、生命周期结束的资产有哪些」 |
| Step2 卡片返回列表 | 返回列表并给退役链接 | 卡片列出资产并附退役链接 |
| Step3 确认退役 | 调用退役创建工单接口 | 点击「确认退役」链接后调用退役创建工单接口，完成退役流程发起；输入参数为卡片中的资产列表（属性含资产名称、资产规格、资产标签） |
| Step4 返回结果 | 卡片返回工单创建结果 | 返回工单创建结果及属性，提供可点击查看链接 |

#### 3.1.2 退役技术处理修改点

| 修改点 | 说明 |
| --- | --- |
| 删除「计划退役时间」输入 | 内置流程中删除该输入项；此前用户输入后技术处理会回写资产「计划退役时间」，业务上不满足实际情况 |
| 「所属部门」置空 | 增加逻辑：资产退役后将属性「所属部门」置为空；退役资产不再属于业务部门，不计为有效资产，不影响部门盘点清单 |

#### 3.1.3 退役查询意图字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 退役场景 | 生命周期自然结束 | 达到预设折旧年限、财务价值归零、已到计划退役时间 |
| 退役场景 | 硬件老化/故障 | 设备频繁宕机、维修成本超残值；TCO 已超基准成本 |

### 3.2 资产盘点过程完整闭环

#### 3.2.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 现状 | 先建模板选盘点对象，再建计划选盘点人和周期 | 自动生成盘点任务 |
| 痛点-操作繁琐 | 5-6 步 | 选择资产 → 保存模板 → 选择执行人/周期 → 生成计划 → 生成任务 |
| 痛点-学习成本高 | 概念难懂 | 需理解「模板/计划/任务」区别及字段含义，操作前需培训 |
| AI 目标 | 自然语言一键生成盘点任务 | 用 Dify 工作流编排 + 前端 AI 助手实现 |
| 效率目标 | 3-5 分钟 → 15 秒内 | 将盘点任务创建耗时降至 15 秒以内 |
| 体验目标 | 免培训 | 像聊天一样下达指令即可完成创建 |
| 缺参补充 | 主动追问 | 关键参数缺失时系统主动提示补充 |

#### 3.2.2 盘点 AI 工作流（Dify）

```
[开始] → [知识库检索] → [LLM 意图识别与参数提取]
 → [条件分支：信息是否完整？]
 ├── 否 → [LLM 追问生成] → [回复]
 └── 是 → [HTTP-查询 ITAM 资产]
        → [HTTP-创建模板]
        → [HTTP-创建计划]
        → [HTTP-生成任务]
        → [回复结果卡片]
```

- 输入示例：「帮我安排一下，北京分公司所有笔记本电脑，让王工负责，每月1号盘点一次」→ 自动完成模板、计划、任务创建。
- 价值：任务自动生成（精准到人到物）、执行过程实时可视、结果自动比对差异一键溯源。
- 要求：多维穿透（打通台账数据源，实现索引关联查询及统计）、语义泛化（理解「空闲」「快过保」等口语并转精确查询条件）。

### 3.7 验收标准（源文档量化指标）

| 验收项 | 目标标准 | 验证方式 | 备注 |
| --- | --- | --- | --- |
| 意图识别准确率 | 业务口语转查询条件准确率 ≥ 95% | 构造 200 条覆盖各场景测试语句，人工标注标准答案比对 AI 输出 | AI 知道用户要干什么 |
| 召回率 | 符合条件资产召回率 ≥ 95% | 对每条查询类语句预先用 SQL 标定真实结果集，比对 AI 返回 | 允许漏掉少量数据 |
| 准确率 | 返回结果正确率 100% | 对每条查询类语句用 SQL 标定真实结果集比对，保证 AI「不乱说」 | 不允许结果错误，否则导致下一步操作失败 |

## 4. 验收标准

- 退役场景：AI 支持四类待退役查询，返回带退役链接的卡片，点击确认退役调用工单接口并回卡片；退役技术处理删除「计划退役时间」输入、退役后「所属部门」置空。
- 盘点场景：一句话经 Dify 工作流生成模板/计划/任务，缺参主动追问，创建耗时 ≤ 15 秒。
- 维护场景：一句话经 Dify 工作流匹配/创建维护项/模板/计划并生成任务。
- 数据透视：自然语言查询可返回列表、统计与可视化图表及结论。
- 资产申请：AI 自动填充直属上级、推荐领用地点与规格。
- OA 对接：入职/离职自动发起资产分配/回收流程。
- 满足意图识别准确率 ≥ 95%、召回率 ≥ 95%、准确率 100% 的量化验收指标。
