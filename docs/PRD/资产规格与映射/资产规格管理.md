## 2. 需求分析

### 2.1 业务背景

资产规格（规格）是企业资产实例化的来源。企业在创建具体资产（硬件、消耗品、软件许可、合同）之前，需要先定义其规格模型：规格定义可基于供应商标准（如「Apple MacBook Pro」），也可基于自定义抽象（如「Graphic Designer Workstation」）。规格集中定义了型号、制造商、成本、折旧、生命周期等信息，资产创建时继承规格属性，从而保证资产数据的规范一致，并为补货、合规、成本核算提供基础。

围绕规格，系统还需支持：规格生命周期跟踪（识别接近停售/停支持/退役的规格以做风险与替换规划）、兼容与替代关系维护（补货时可用兼容/替代规格顶替）、软件升降级授权（软件合规检查）、以及将规格发布到服务目录（支撑领用/采购流程选品）。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **标准化实例化来源**：资产由规格实例化，统一型号、成本、折旧、生命周期，降低录入成本与数据错误。
- **风险与合规管理**：通过规格生命周期跟踪 EOS/EOL，识别过时规格；通过软件升降级支撑合规计算。
- **补货灵活性**：兼容/替代规格在目标规格停产或缺货时提供顶替选项。
- **成本控制**：规格集中维护成本、折旧、残值，支撑资产价值核算。
- **流程打通**：规格可发布到 DOSM 服务目录，支撑领用/调拨/采购选品。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow 规格管理（Product 规格）：规格按类型（硬件/软件/耗材/合同）分表存储，共用基础表 `cmdb_model`；规格与 category 关联决定 asset class；规格支持生命周期（`cmdb_model_lifecycle`）跟踪六阶段；软件规格支持升降级（`cmdb_m2m_downgrade_model`）用于合规；规格发布到目录形成自助服务项。本方案对齐该模式，去品牌化并适配 CMDB 对接。

### 2.3 用户故事

- 作为**规格管理员（model_manager）**，我希望为不同类型实物创建规格并维护通用/专属字段，以便资产可基于规格快速实例化。
- 作为**SAM 软件资产经理**，我希望维护软件规格及其升降级关系，以便进行软件合规计算。
- 作为**IT 运维**，我希望为规格维护兼容/替代规格，以便在补货时选用可顶替的设备。
- 作为**资产管理员**，我希望跟踪规格生命周期阶段，以便提前规划升级或替换过时规格。

### 3.9 兼容规格（Compatible 规格）

> 角色：model_manager。兼容关系为**双向**：一次添加，A、B 互为对方的兼容规格，双方兼容规格页均可见。

#### 3.9.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 硬件加兼容规格 | 为硬件规格添加兼容规格 | 入口：硬件 models 列表页点 名称 进详情 → Compatibles 页签；可选 hardware+software+consumable 规格（排除系统默认），支持模糊搜索批量勾选；提交 后列表显示且数量正确 |
| 消耗品加兼容规格 | 为消耗品规格添加兼容规格 | 入口 耗材 models 详情；可选全部 hardware+software+consumable 规格 |
| 软件加兼容规格 | 为软件规格添加兼容规格 | 入口 软件 models 详情；仅可选未成为 bundled 规格 的规格 |
| 排除 bundle 组件 | 约束 | 已成为 bundled 规格 组件中的规格不能作为 compatible 规格 |
| 重复校验 | 防重复 | 添加重复兼容时点 保存 判重，已存在则提示「This compatible already exists, please select the others」 |
| 删除兼容 | 删除关联 | Compatibles 列表每条记录有 delete，点后二次确认「Yes」删除该条兼容关系，规格本身不变 |
| 搜索公共能力 | 下拉搜索弹窗 | 点搜索 logo 弹出展示页，显示 规格分类 名称、名称、规格编号；支持 筛选 |

#### 3.9.2 字段说明

### 3.13 页面功能与交互逻辑

#### 3.13.1 列表页（各类型规格）

- **入口分栏**：硬件 / 软件 / 耗材 / 合同 models 各自独立列表页。
- **默认列**：名称、CI class 挂到 category 后显示对应名称，无值为空、制造商、规格编号、状态 等；支持列设置调整。
- **搜索**：按类型对应的搜索条件组合模糊搜索（回车触发），结果为空不显示数据，筛选条件展示在漏斗中且统计正确。
- **操作**：New、编辑（点 名称 进详情）、复选批量删除（More→删除，二次确认）。
- **页签 限制**：最多打开 10 个 tab，超出提示「Max 页签 Reached」。

#### 3.13.2 详情页（规格）

- 展示规格全部字段及当前值，可直接编辑并提交（未实例化时）。
- 页签 分组：基础字段、规格 Lifecycles、Compatibles、Substitutes、（软件另有）Downgrade/Upgrade、详见《发布到产品目录》。
- 实例化保护：规格下有实例化数据时，提交/删除 置灰、字段不可修改。

## 4. 验收标准

- 硬件/消耗品/软件/合同四类规格均可完成创建、查看、编辑、删除，字段与字典值符合本文定义。
- 已实例化的规格不可编辑/删除（提交/删除 置灰、字段只读）。
- 列表搜索条件按类型正确生效，结果为空不显示数据，页签 超 10 提示。
- 规格生命周期可创建多条，同一 type+phase 唯一，阶段时间不重叠；实例资产遵循规格 lifecycle。
- 兼容规格双向可见、可查重、可删除；替代规格单向、反向可见、可查重、可删除；均排除 bundle 组件规格。
- 软件升降级可创建/删除，规格删除时自动解除升降级关系。
- Product Process 的 文件名 与 Product 引用 唯一校验生效。
