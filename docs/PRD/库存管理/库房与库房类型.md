## 2. 需求分析

### 2.1 业务背景

库房（库房）是存储库存的地方；当某特定库存较低时，库存规则会通知库存管理员或自动从一个库房转移到另一个库房。库房是库存管理应用系统中的独立实体，每个库房拥有自己的库存记录和规则，可独立操作也能相互协作以优化库存管理。企业需要先建立不同的库房位置（以及库房类型分类），才能将库存分配到具体库房，从而更有效地控制库存水平、减少缺货、确保库存在需要时可用。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **库存结构化**：建立库房与库房类型分类，为库存分配、库存规则、服务位置提供物理与逻辑载体。
- **精细化管理**：库房下可维护货架/货位，支持更细粒度的存放定位。
- **协同优化**：库房作为独立实体可相互协作（转移补货），支撑缺货预警与自动补货。
- **可扩展分类**：库房类型支持自定义，满足内部/外部、不同优先级的分类需求。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow Inventory Management：库房（库房）为独立实体，含分配组、位置、类型、经理、经纬度、外部标记等属性；库房类型（库房 类型）预置优先级；创建库房时可维护货架/货位。本方案对齐其字段与创建流程，并结合本系统删除 Domain 字段、暂缓 需要发货 的落地策略。

### 2.3 用户故事

- 作为**库存管理员（inventory_user）**，我希望创建库房并设置分配组、位置、类型、经理、经纬度、外部标记，以便建立库存存放地点。
- 作为**库存管理员**，我希望在库房创建时直接添加货架与货位，以便细化存放定位。
- 作为**库存管理员（inventory_admin）**，我希望在系统预置库房类型不满足时新建库房类型（含优先级），以便灵活分类。
- 作为**库存管理员（inventory_admin）**，我希望在库房无库存/库存已转移后删除库房，以便清理无效库房。

## 3. 需求设计

### 3.1 库房（库房）

> 参考截图：page_064~073、p1129。入口：Product catalog → Inventory Management → All stockrooms 列表页。

#### 3.1.1 涉及到的表

- `alm_stockroom`（库房表）
- `alm_stockroom_type`（库房类型表，引用 类型）
- `cmn_location`（位置表，引用 位置）
- `sys_user` / `sys_user_group`（管理员/分配组引用）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 | 角色 |
| --- | --- | --- | --- |
| 创建库房 | 点击 New 进入新增详情页，填写字段后 提交 | assignment group 下拉引用组织数据；location 支持省/市/国家/街道多级下拉；type 引用库房类型下拉；manager 引用数据字典显示 First 名称+Last 名称；External 复选框默认取所选 type 的 external 字段值 | asset、inventory_user |
| 添加货架/货位 | 新增页可点击「新增 shelf」新增一个货架同时增加一个货位；点击「新增 slot」在当前货架下新增一个可输入货位 | 货架、货位定义同 DCIM，可直接输入 | asset、inventory_user |
| 查看库房 | All stockrooms 列表页点击名称进入详情页查看 | 创建成功后 All stockrooms 数量 +1 | admin、asset |
| 编辑库房 | 详情页修改字段后 提交 | 库房信息被成功修改 | asset、inventory_user |
| 删除库房 | 库房无库存或库存全部转移后，详情页下方点击 删除 | 删除后列表不再显示该记录，库房总数量 -1 | inventory_admin |

#### 3.1.3 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 名称 | VARCHAR | 100 | 必填，库房名称（如 `Stockroom1`） |
| 全称 | VARCHAR | 100 | 留空默认取名称 |
| 分配组/主用群组 | VARCHAR | 64 | 主要使用该库房的用户组，下拉引用组织数据 |
| 位置 | VARCHAR | 64 | 库房物理位置，下拉多级选择（省/市/国家/街道，如 `Asia/China/BeijingCity`） |
| 库房类型 | VARCHAR | 64 | 必填，引用库房类型（下拉） |
| 库房经理/管理员 | VARCHAR | 32 | 库房经理，引用数据字典显示 First 名称+Last 名称；触发库房预警时的默认通知者 |
| 纬度 | VARCHAR | 20 | 库房地理位置纬度 |
| 经度 | VARCHAR | 20 | 库房地理位置经度 |
| 外部 | BOOLEAN | - | 是否为外部库房；默认取所选 type 的 external 值，可修改 |
| 货架 | VARCHAR | 64 | 库房内货架，可直接输入，定义同 DCIM |
| 货位 | VARCHAR | 64 | 货架下货位，可直接输入，定义同 DCIM |

#### 3.1.4 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| External | true | 外部库房：位于组织外部或与外部系统/供应商关联；默认由库房类型 external 决定 |
| External | false | 内部库房 |

### 3.4 页面功能与交互逻辑

#### 3.4.1 库房列表页（`/inventory/stockroom`，All stockrooms）

- 默认展示列：名称/全称、类型、分配组、位置、管理人、External。
- 操作：搜索（名称/全称）、新建、编辑（名称蓝链进详情）、删除，二次确认。
- 计数：创建成功后 All stockrooms 数量 +1；删除后 -1，计数准确。

#### 3.4.2 库房详情页（`/inventory/stockroom/:id`）

- 真实系统含「详情/服务位置/货架/资产」页签（page_068）；本原型将货架、服务位置拆为独立列表页管理（见《服务位置关联》PRD 与货架列表）。
- 创建页可 新增 shelf / 新增 slot 维护货架货位。
- 深链访问不存在库房 ID 时展示 404 结果页与返回入口。

#### 3.4.3 货架列表页（`/inventory/shelf`）

- 字段：全称（留空默认取「所属库房/名称」）、名称（如 `Shelf1`）、所属库房（下拉引用库房）、位置（下拉）、创建人/创建时间（只读）。
- 操作：搜索、新建、编辑、删除。

#### 3.4.4 库房类型列表页（`/inventory/stockroom-type`）

- 默认展示列：名称、描述、优先级、外部库房、需要发货。
- 操作：搜索（名称）、新建、编辑（名称蓝链）、删除（二次确认）。

### 3.5 日志审计

对库房/库房类型/货架的新增、编辑、删除操作记录统一操作日志，格式参考：【操作人】于【时间】对模块【库存管理/库房】执行了【新增/编辑/删除】操作，操作内容为【库房名称】，操作结果为【成功/失败】。

## 4. 验收标准

- 库房可完成创建、查看、编辑、删除全流程，字段与字典值符合本文定义；创建/删除后 All stockrooms 计数准确。
- 库房创建时 assignment group/location/type/manager 下拉引用正确，External 默认取库房类型 external 值且可修改。
- 库房创建页可 新增 shelf / 新增 slot 正确维护货架与货位。
- 库房类型可创建、查看、编辑、删除；Domain 字段不出现，需要发货 保留字段但不触发物流逻辑。
- 删除库房受「无库存/库存已转移」约束（业务提示）。
