## 2. 需求分析

### 2.1 业务背景

截图跨多产品家族部署，ITAM 之外存在用户中心兄弟产品，统一维护组织机构、用户账号与角色权限。ITAM 的资产责属（分配给 / 归属人 / 管理人 / 部门）、CI 负责人与归属组织均依赖用户中心的组织与用户数据。本模块在同一原型模板中补齐用户中心核心页面：组织机构（树）、用户管理（列表/详情）、角色管理（列表/详情）。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **统一身份底座**：集中管理组织、用户、角色，为各产品提供一致的身份与归属数据。
- **层级化组织**：以自引用树维护部门层级，支撑资产/成本按组织归集与数据权限划分。
- **角色化授权**：以角色聚合权限，用户绑定角色即获得对应菜单权限，降低授权维护成本。
- **责属可追溯**：用户归属部门/角色明确，配合资产责属字段实现责任到人。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow 的 用户 / 分组 / 角色 模型与部门树：用户归属部门与组，角色聚合权限；组织采用层级结构。本原型简化：角色权限以单一菜单权限复选组表达（截图区分功能授权/数据授权/配置用户）；组织机构删除不级联（子节点成为孤儿）；截图中的「人数/启用人数」统计值不实现（见第 6 节）。

### 2.3 用户故事

- 作为**系统管理员**，我希望以树形维护部门层级，以便组织资产与用户归属。
- 作为**IT 管理员**，我希望创建用户账号并绑定部门与角色，以便快速开通与授权。
- 作为**权限管理员**，我希望定义角色及其菜单权限，以便批量控制用户可访问范围。

## 3. 需求设计

### 3.1 组织机构（自引用树）

#### 3.1.1 涉及到的表

- `orgUnits`（组织机构表，`OrgUnitSchema`，`parentId` 自引用）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 机构树展示 | 左侧卡片以树形展示机构层级 | 由扁平集合按 `parentId` 递归组装（`''` 为根）；默认展开全部节点 |
| 新建根机构 | 新建顶级机构 | 点击「新建根机构」，`parentId=''`，表单默认 状态=启用、类型=部门 |
| 新增下级 | 在选中节点下新建子机构 | 需先选中节点；`parentId=选中节点`，保存后自动展开父节点并选中新节点 |
| 编辑机构 | 选中节点在右侧面板编辑 | 选中节点回填表单，保存更新 |
| 删除机构 | 删除选中节点，不级联 | Popconfirm「确认删除该机构？不会级联删除子机构」；子节点成为孤儿 |
| 上级机构下拉 | 编辑时上级机构可选 | 选项排除「自身及其所有后代」，避免形成环；含「（根机构）」选项 |

#### 3.1.3 字段说明

字段来源：`orgUnits.ts` 的 `OrgUnitSchema`。

| 字段名 | 数据类型 | 长度 | 备注说明 |

| 状态 | VARCHAR | - | 启用 / 停用，必填 |
| 机构城市 | VARCHAR | 50 | `maxLength=50`，如「北京」 |
| 机构类型 | VARCHAR | 50 | `maxLength=50`，如 总部/集团/部门 |
| 机构电话 | VARCHAR | 50 | `maxLength=50` |
| 机构地址 | VARCHAR | 200 | `maxLength=200` |
| 负责人 | VARCHAR | 50 | `maxLength=50` |

### 3.4 页面功能与交互逻辑

#### 3.4.1 组织机构（`/user-center/org`）

- **布局**：左「机构树」卡片（宽 320，含 新建根机构/新增下级/删除 三按钮）+ 右「机构详情」卡片（编辑表单）。
- **交互**：默认展开全部节点；选中节点右侧回填并可编辑；新增下级需先选节点；删除不级联；上级机构下拉排除自身及后代。
- **空态**：未选节点右侧展示「请选择左侧机构节点，或新建机构」。

#### 3.4.2 用户管理（`/user-center/users`、`/:id`）

- **列表列**：用户名（可点击进详情）、姓名、邮箱、部门、角色、状态（标签）、操作（删除）。
- **详情/新建表单**：用户名、姓名、邮箱、手机号、部门（下拉）、角色（下拉）、状态；必填 用户名/姓名/状态；邮箱格式校验。
- **404 守卫**：访问不存在用户 ID 展示「未找到该用户」结果页与「返回用户管理」入口。

#### 3.4.3 角色管理（`/user-center/roles`、`/:id`）

- **列表列**：角色名（可点击进详情）、编码、描述、用户数、操作（删除）。
- **详情/新建表单**：角色名、编码、描述、权限（复选组）；必填 角色名/编码；用户数不可编辑。
- **404 守卫**：访问不存在角色 ID 展示「未找到该角色」结果页与「返回角色管理」入口。

## 4. 验收标准

- 组织机构以左树+右详情面板维护，支持新建根/下级、编辑、删除（不级联）；上级机构下拉排除自身及后代。
- 用户管理可完成增删改查；部门/角色下拉分别联动组织机构与角色；邮箱格式校验、404 守卫生效。
- 角色管理可完成增删改查；权限复选组来自固定权限池；用户数为统计值不可编辑，新建默认 0。
- 各字段与字典值符合本文定义。

## 6. 简化说明（原型范围）

- **组织机构无级联删除**：删除仅移除当前节点，子节点成为孤儿（同位置管理）；截图中的「人数/启用人数」统计值本原型不实现。
- **角色权限简化**：截图区分功能授权/数据授权/配置用户，本原型以单一菜单权限复选组表达。
- **用户数只读**：`userCount` 由系统统计，不在表单编辑，新建默认 0。
