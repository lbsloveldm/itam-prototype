## 2. 需求分析

### 2.1 业务背景

资产的全生命周期都应有记录，「删除」是生命周期的终结而非「从未存在」。物理删除会破坏审计追踪与数据完整性，易被用于掩盖盗窃、丢失或违规处置。系统需采用逻辑删除并提供回收站，支持查看、恢复与彻底删除，满足安全审计、责任追溯、数据完整性与误操作恢复诉求。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **安全与审计**：防止恶意删除掩盖违规行为；满足 SOX、ISO27001 等合规对删除操作的审计追踪要求。
- **责任追溯**：明确「谁操作、谁负责」，快速定位责任人与删除上下文。
- **数据完整性与历史追踪**：保留资产完整生命周期，删除操作可追溯被删信息，辅助恢复或重建。
- **误操作恢复**：误删时管理员可通过记录快速定位并恢复。

#### 2.2.2 调研结论及竞品分析

主流 ITAM/CMDB 产品普遍采用软删除 + 回收站/归档机制，保留删除快照与操作人时间戳，并提供恢复能力。本方案在此基础上补充删除原因、许可证 校验恢复与批量恢复。

### 2.3 用户故事

- 作为**资产管理员**，我希望删除的资产进入回收站而非被物理清除，以便误删后可恢复。
- 作为**审计人员**，我希望查看删除人、删除时间与删除原因，以便追溯责任。
- 作为**合同管理员**，我希望恢复误删的合同，以便保证合同数据完整。

## 3. 需求设计

### 3.1 逻辑删除（软删除）机制

#### 3.1.1 涉及到的表

- `asset`（资产主表，含 `is_deleted`、`deleted_by`、`deleted_time`、`delete_reason` 等字段）
- `contract`（合同主表，含删除标记与删除信息字段）
- `recycle_bin`（回收站视图/归档，聚合已删除资产快照）
- `activity_log`（统一日志表，记录删除/恢复）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 逻辑删除 | 执行「删除」时不物理删除记录 | 仅将记录标记为「已删除」状态，数据完整保留在「已删除/归档」区域 |
| 删除后可见性 | 已删除资产不出现在常规列表 | 该资产不再出现在常规资产列表与统计中 |
| 删除快照 | 记录删除信息 | 记录执行删除的用户、时间戳及被删除资产的完整信息快照 |

### 3.2 已删除记录展示（回收站）

#### 3.2.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 回收站入口 | 在资产洞察下方新增「回收站」 | 点击后默认显示被删除的资产 |
| 列表不可点击 | 展示的数据不可点击 | 名称字段取值：资产取「资产全称」，合同取「名称」 |
| 搜索 | 支持搜索 | 支持按删除时间、资产类型搜索；匹配不到类型的统一归在「其他」 |
| 删除人展示 | 姓名+用户名 | 格式「姓名（用户名）」，保证唯一，举例：张三(00086) |
| 删除确认页 | 展示名称并可填删除原因 | 展示要删除的名称字段值；「删除原因」非必填，作为字段展示在资产/合同删除日志记录中 |

#### 3.2.2 字段说明（回收站列表）

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 资产标识 | VARCHAR | 40 | 被删除资产的 资产标识 |
| 名称 | VARCHAR | 128 | 资产取「资产全称」，合同取「名称」 |
| 类型 | VARCHAR | 32 | 资产类型；无法匹配的归「其他」 |
| 原状态 | VARCHAR | 40 | 删除前资产状态 |
| 删除人 | VARCHAR | 64 | 姓名（用户名），保证唯一 |
| 删除时间 | TIMESTAMP | - | 删除操作时间，支持按其搜索 |
| 删除原因 | VARCHAR | 500 | 删除确认页填写（非必填），记入删除日志 |

#### 3.2.3 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 类型 | 硬件 / 软件 / 耗材 / 云 / 捆绑 / 托盘 / 合同 / 其他 | 无法匹配到具体类型统一归「其他」 |

### 3.3 恢复已被删除的数据

#### 3.3.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 单条恢复 | 列表操作「恢复」 | 点击「恢复」后当前页面弹出恢复确认弹窗 |
| 许可证 校验 | 恢复前校验许可数量 | 恢复时校验客户 许可证 数量是否足够，足够时恢复成功 |
| 恢复结果 | 恢复后回台账 | 确认恢复后，资产/合同台账中可查到该数据；回收站不再显示已恢复资产；日志包括删除记录及恢复记录 |
| 批量恢复 | 支持批量恢复 | 「更多」中增加批量恢复 |
| 任务不联动恢复 | 维护/盘点任务不恢复 | 依赖计划、模版产生的任务，当恢复计划、模版后，原来依赖该被删除对象生成的任务不需要恢复 |

### 3.4 恢复已被删除的合同数据

#### 3.4.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 合同删除记录入口 | 合同管理菜单下增加「合同删除记录」 | 点击后进入列表页，支持搜索 |
| 删除人展示 | 姓名+用户名 | 格式「姓名（用户名）」，保证唯一，举例：张三(00086) |
| 合同删除确认页 | 展示合同名称并可填删除原因 | 「删除原因」非必填，作为字段展示在删除记录中 |
| 合同恢复 | 列表操作「恢复」 | 弹出恢复确认弹窗，展示相关信息并提供恢复备注供填写 |
| 恢复结果 | 恢复后回合同管理 | 确认恢复后，合同管理中可查到该合同；日志包括删除记录及恢复记录 |

### 3.5 基础对象「启用/停用」（hold）

> 说明：本节为 hold 需求，用于解决删除对象导致关联记录成为「孤儿数据」的问题；本期不实现，留作规划。

#### 3.5.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 增加「是否启用」字段 | 涉及对象增加该属性 | 详情页增加「是否启用」开关 |
| 列表启用/停用操作 | 列表显示「启用/停用」 | 操作启用则「是否启用」为「是」，停用则为「否」 |
| 停用影响 | 历史数据不动 | 历史数据完全不动（资产仍挂原位置/库房，可继续报废、折旧、盘点）；新增时下拉不再出现已停用对象 |
| 启用影响 | 恢复可选 | 新建时下拉出现已启用对象 |

#### 3.5.2 涉及的基础对象

- 所有资产规格（硬件、软件、耗材、云资产、捆绑、托盘、合同）
- 所有规格分类
- 库房类型、库房、库存规则
- 位置、公司、成本中心、折旧方案、人工费率卡、任务费率卡
- 许可证 配置（许可证类型、许可证度量指标、指标属性、软件产品、回收规则）

### 3.6 页面功能与交互逻辑

- 回收站列表默认展示已删除资产；数据行不可点击进入详情。
- 列表列：资产标识、名称、类型、原状态、删除人、删除时间；操作：恢复、彻底删除（二次确认，彻底删除不可恢复）。
- 支持按资产标识/名称搜索，按删除时间、资产类型筛选。

### 3.7 日志审计

删除与恢复均写入统一 activity 日志，格式示例：【操作人】于【时间】对模块【回收站/资产】执行了【恢复】操作，操作内容为【资产全称/删除原因】，操作结果为【成功/失败】。

### 3.8 其他说明

- 需要考虑移动端适配问题。

## 4. 验收标准

- 删除资产/合同为逻辑删除，记录进入回收站/合同删除记录并保留完整快照。
- 回收站列表展示资产标识、名称、类型、原状态、删除人（姓名（用户名））、删除时间；数据不可点击；支持搜索与按删除时间/类型筛选，未匹配类型归「其他」。
- 删除确认页可填写删除原因（非必填），并记入删除日志。
- 支持单条恢复与批量恢复；恢复前做 许可证 数量校验；恢复后台账可见、回收站移除，日志含删除与恢复记录。
- 依赖被删除计划/模版生成的维护、盘点任务不随之恢复。
