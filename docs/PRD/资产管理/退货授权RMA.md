## 2. 需求分析

### 2.1 业务背景

在资产管理中，退货授权，归还 Merchandise Authorization是用于管理资产（如硬件设备、备件等）退货、维修或更换的标准流程。它确保资产从申请退货到处理完成的每一步都清晰记录、可追踪，并符合组织的合规性和成本控制要求。

**场景示例（企业笔记本电脑故障退货）**：某公司资产管理员 Alex 发现某办公笔记本频繁死机，IT 初步诊断为主板故障，标记为 故障。RMA 流程如下：
1. **提交申请**：Alex 通过 ITSM 提交 RMA 请求，填写设备型号（macbook 2023）、序列号、故障描述，选择相关维保合同。
2. **审批与验证**：IT 运维团队确认设备在保修范围内，批准免费维修，触发邮件通知 Alex 和供应商（Apple），并记录供应商 RMA 编号（如 RMA-20250318-001）。
3. **物流安排**：供应商表示需退回维修中心，库存管理员打包贴标退回，物流信息实时同步系统，显示「运输中」。
4. **维修处理**：Apple 收到设备检测确认主板故障，更换主板/更换新资产，系统标记「维修中」。
5. **资产返回与验收**：维修/更换后寄回公司，填写返回物流信息，库存管理员验收到货，IT/资产管理员验收测试确认故障解决，资产记录更新为「已维修」，RMA 工单关闭，记录存档。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **退修可追踪**：RMA 全流程节点记录，退货/维修/更换每一步可追溯，含供应商 RMA 编号。
- **合规与成本控制**：结合 warranty 维保合同判断是否免费维修，控制维修成本。
- **状态一致**：故障→待维修→运输→维修中→到货验收，各节点自动推进资产状态。
- **维修与更换双路径**：支持现场维修、返厂维修（Repair）与更换（Replace）后注册新资产。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow/主流 ITAM 的 RMA 能力：故障资产（故障）发起退修，经供应商决策维修或更换，维修返回后验收入库，更换则注册新资产并处置原资产。ITAM 强化了现场/离场分支、维保合同校验及到货库房货架货位的细化选择。

### 2.3 用户故事

- 作为**资产管理员**，我希望对故障资产发起 RMA 并选择维保合同，以便走保内维修/更换。
- 作为**IT 运维**，我希望评估决定现场维修或返厂，并记录供应商 RMA 决策，以便流程清晰。
- 作为**库存管理员**，我希望在到货节点录入到货数量、序列号与库房货架货位，以便准确入库或注册更换资产。

## 3. 需求设计

### 3.1 RMA 流程总览

RMA 从故障资产发起，经评估分为现场维修与离场（返厂）两条主路径：

**RMA → 评估**
- **现场→ 现场维修**：修好→ RMA 流程结束；未修好→ 转入离场路径的 Shipment。
- **离场→ 运输→ 供应商 RMA 决策**：
  - **维修→ 接收维修后资产→ 验收/评估**
  - **更换→ 注册并接收更换资产**

工单节点序列（流程编排）：Start → 请求→ 审批→〔现场/离场分支〕→ 运输→ 供应商决策→〔Repair：返回运输→ 资产到货→ 验收〕/〔Replace：替代到货〕→ End。审批不通过（供应商 拒绝）可回退。

#### 3.1.1 涉及到的表

- `asset`（资产主表，读取故障资产、变更 state/substate、库房位置）
- `contract` / `contract_asset`（warranty 维保合同及关联表）
- `stockroom`（库房+货架+货位）
- `workflow_instance` / `workflow_node`（RMA 工单与节点自动化配置）

#### 3.1.2 各节点功能与流程自动化

| 节点 | 功能描述 | 流程自动化（触发内容） |
| --- | --- | --- |
| 请求 | 选择故障资产。数据来源于 ITAM 资产，同时满足：state=in stock、substate=defective、type=hardware。操作：单选、必填，顶部支持搜索 | 名称=Request，条件=工单离开节点，选择节点=Request，接口调用，立即执行。触发内容：将选中资产 substate 更改为 **待处理 Repair** |
| 审批 | 选择维修依据的维保合同并审批。合同数据满足：合同状态=启用、合同下包含工单中选择的资产、合同类型=warranty。操作：必填、单选，顶部支持搜索、排序、分页；选择完成后回显 DOSM | — |
| 运输 | 选择运输库房（下拉单选，通过 API 调用，数据来源 ITAM 库房名称），资产发出 | 名称=Shipment，选择节点=Shipment，接口调用，立即执行。触发内容：将 RMA 资产的 state 更改为 **in transit** |
| 供应商 RMA 决策 | 供应商决定维修或更换 | 名称=供应商 RMA decision，选择节点=供应商 RMA decision，接口调用，立即执行。触发内容：将 RMA 资产的 state 更改为 **in maintain** |
| 资产到货，Repair 路径 | 库存管理员接收维修后返回的资产 | 见 3.2 到货入库逻辑 |
| 验收/评估 | 验收维修结果 | 名称=Evaluation，选择节点=Evaluation，接口调用，立即执行。触发内容：当 Evaluation result=可用→ 将资产 substate 更改为 **available**；当 Evaluation result=不可用→ 将维修资产 substate 更改为 **待处理 Repair**（等待维修） |
| 替代到货，Replace 路径 | 接收并注册更换的新资产，原资产报废 | 名称=Replace 资产 receive，选择节点=接收，接口调用，立即执行。触发内容：将原 RMA 资产 state 更改为 **已退役**（报废），substate 更改为 **供应商 credit**（供应商处置） |

### 3.2 到货/替代到货页面（接收）

到货页面用于录入维修返回或更换新资产的到货信息，含一级弹窗（到货明细）与二级弹窗（Capture 资产标识）。

#### 3.2.1 一级弹窗字段说明

| 字段名 | 数据类型 | 是否必填 | 是否可编辑 | 备注说明 |
| --- | --- | --- | --- | --- |
| RMA 资产规格名称 | 展示 | - | 否 | 左侧展示 RMA 资产的规格名称 |
| Remaining 数量 | 数字 | - | 否 | 默认为 1 |
| Receiving 数量 | 整数 | 是 | 是 | 数据来源于填写实际到货资产数量，自动回填；不可大于 Remaining 数量 |
| 单位 成本 | 数字（两位小数） | 是 | 是 | 单价 |
| Receiving 库房 | 下拉搜索单选 | 是 | 是 | 库房，默认为上一节点（运输）选择的库房名称，无需选择最小节点（含货架、货位） |

#### 3.2.2 二级弹窗（Capture 资产标识）

### 3.4 字段字典值说明（RMA 状态机）

| 阶段/字段 | 字典值 | 说明 |
| --- | --- | --- |
| Request 候选条件 | state=in stock, substate=defective, type=hardware | 故障硬件资产可发起 RMA |
| Request 后 | substate=待处理 Repair | 选中资产进入待维修 |
| Approval 合同条件 | 合同状态=启用, 合同含工单资产, 合同类型=warranty | 保内维修依据 |
| Shipment 后 | state=in transit | 资产发出运输中 |
| 供应商 RMA decision 后 | state=in maintain | 供应商处维修中 |
| Evaluation 结果 | available → substate=available | 验收可用，回到可用态 |
| Evaluation 结果 | unavailable → substate=待处理 Repair | 验收不可用，重回待维修 |
| Replace 资产 receive 后（原资产） | state=已退役, substate=供应商 credit | 更换后原资产报废、供应商处置 |
| Replace 新资产创建 | state=in stock, substate=available | 更换到货注册新资产入库可用 |
| On-site repair | Yes → RMA 流程结束 | 现场修复完成即结束 |

## 4. 验收标准

- RMA 流程可从故障资产（state=in stock、substate=defective、type=hardware）发起，Request 单选必填，选中后 substate=待处理 Repair。
- Approval 可选择满足条件的 warranty 维保合同（启用、含工单资产、warranty 类型）。
- 现场维修 Yes 即结束流程；离场路径 Shipment→供应商 RMA decision 状态依次变为 in transit、in maintain。
- Repair 路径：到货验收 Evaluation 结果 available→substate=available，unavailable→substate=待处理 Repair。
- Replace 路径：替代到货按字段映射创建新资产（state=in stock/substate=available），原资产 state=已退役/substate=供应商 credit；Serial 编号 重复校验与 Receiving 数量 上限校验生效。
- 到货节点可选择库房+货架+货位，补充逻辑（维修资产库房位置随运输节点、in maintain→in transit）生效。
