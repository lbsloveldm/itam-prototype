## 2. 需求分析

### 2.1 业务背景

在客户实际项目沟通中发现，客户希望提供批量转移资产功能；客户不使用我们的流程，也不提供对接客户的 OA，因此需要在功能中提供**批量移交资产能力**（比如：用户离职后，其名下资产给到其他用户）。资产移交是一个不依赖复杂审批流程的轻量能力，通过「发起—接收人确认/拒绝—所有者更新」三步完成资产责任人的转移。

### 2.2 场景解读

| 角色 | 说明 | 业务诉求 |
| --- | --- | --- |
| 发起人（现资产负责人） | 当前资产的负责人，如离职/转岗人员 | 快速将名下资产批量移交给其他用户 |
| 接收人 | 接收资产的新负责人 | 在待办中确认或拒绝接收资产 |
| 资产管理员 | 管理台账 | 无需走完整流程即可完成资产责任人变更 |

### 2.3 竞品分析结论

竞品多以流程审批实现资产转移；本需求面向不使用流程/OA 的客户，提供更轻量的批量移交能力，降低使用门槛，同时通过资产状态校验保证数据正确。

### 2.4 用户故事

- 作为**资产负责人**，我希望选择名下资产批量发起移交并指定接收人，以便离职/转岗时快速交接。
- 作为**接收人**，我希望在待办中确认或拒绝移交，以便掌控自己名下资产。
- 作为**资产管理员**，我希望移交仅在合法资产状态下变更所有者，以便台账准确。

## 3. 需求设计

### 3.1 主要思路

1. 发起资产移交，并选择接收人，生成待确认任务。
2. 接收人确认/拒绝。
3. 资产所有者更新。
4. 资产状态为「在库/在用/使用中/运行中/待分配」时，才允许变更资产所有者，否则不允许变更。

### 3.2 资产移交

#### 3.2.1 涉及到的表

- `asset`（资产主表，读取资产状态并更新资产所有者）
- `asset_transfer`（资产移交申请单表，记录移交编号、发起人、接收人、移交状态）

#### 3.2.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 发起资产移交 | 在台账各资产类型下选择资产后，「更多」中增加「资产移交」选项 | 点击后在当前页弹窗展示移交页面 |
| 填写接收人 | 在弹窗填写对应的接收人信息 | 接收方只能选一个人 |
| 提交申请 | 点击提交后自动生成移交申请 | 移交编号规则 `Trans+8位数字`（如 Trans00001112）；资产状态为「在库/在用/使用中/运行中/待分配」时提交成功，否则失败提示「资产状态异常，无法移交」 |
| 我的待办 | 接收人查看待确认的移交申请 | 可对「我的待办」中数据取消/删除（用系统已有提示），删除后不再展示且不影响资产状态 |
| 我的发起 | 发起人查看已提交的申请 | 可对「我的发起」中数据删除（用系统已有提示），删除后不再展示且不影响资产状态 |
| 确认/拒绝接收 | 接收人在待办详情页确认接收或拒绝接收 | 确认接收：待移交资产的资产所有者由当前负责人改为接收方，移交状态=已接收；拒绝接收：资产所有者不变，移交状态=已拒绝；处理后从待办移入「我的已办」，发起人「我的发起」状态同步更新 |
| 确认时状态校验 | 确认接收时判断资产状态 | 状态为「在库/在用/使用中/运行中/待分配」时确认成功；否则确认失败提示「资产状态异常，拒绝接收」，点击确认后移交单状态=已拒绝 |
| 我的已办 | 查看已接收/已拒绝的申请 | 可对「我的已办」中数据删除（用系统已有提示），删除后不再展示且不影响资产状态 |

#### 3.2.3 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 资产移交编号 | VARCHAR | 40 | 移交申请单号，规则 `Trans+8位数字` |
| 待移交资产 | 关联多选 | - | 台账中选择的资产（支持批量） |
| 接收人 | VARCHAR | 32 | 接收资产的新负责人，只能选一个人 |
| 发起人 | VARCHAR | 32 | 当前资产负责人 |
| 移交状态 | VARCHAR | 32 | 待接收 / 已接收 / 已拒绝 |
| 资产所有者 | VARCHAR | 32 | 资产负责人，确认接收后更新为接收人 |
| 资产状态 | VARCHAR | 40 | 校验字段，需为可移交状态 |

#### 3.2.4 字段字典值说明（移交状态机）

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 移交状态 | 待接收 | 已提交申请，等待接收人处理 |
| 移交状态 | 已接收 | 接收人确认，资产所有者已更新为接收方 |
| 移交状态 | 已拒绝 | 接收人拒绝或状态校验失败，资产所有者不变 |
| 可移交资产状态 | 在库 / 在用 / 使用中 / 运行中 / 待分配 | 仅这些状态允许发起移交与确认接收 |
| 不可移交处理 | 其他状态 | 提交时提示「资产状态异常，无法移交」；确认时提示「资产状态异常，拒绝接收」 |

### 3.3 页面功能与交互逻辑

- **发起入口**：台账资产各类型下选中资产 →「更多」→「资产移交」，当前页弹窗填写接收人（单选）→ 提交申请。
- **转移资产工作台**：分「我的待办」「我的发起」「我的已办」三视图；删除操作使用系统已有提示，删除仅移除展示记录，不影响资产状态。
- **确认/拒绝**：在「我的待办」点击移交编号进入详情页进行确认接收/拒绝接收；确认成功更新资产所有者并移入已办，发起人视图状态同步。

### 3.4 可能影响模块

- 需要考虑移动端适配问题。
- 日志审计：移交发起、确认/拒绝、删除等操作按日志审计规范记录（操作者、时间、模块、操作、内容、结果）。

## 4. 验收标准

- 台账各资产类型「更多」中可发起资产移交，支持批量选择资产，接收人只能选一个人。
- 提交时校验资产状态，仅「在库/在用/使用中/运行中/待分配」可提交，否则提示「资产状态异常，无法移交」；移交编号规则为 `Trans+8位数字`。
- 接收人确认后资产所有者更新为接收方、状态=已接收；拒绝或状态异常时所有者不变、状态=已拒绝。
- 我的待办/我的发起/我的已办三视图数据与状态同步；删除操作仅移除展示记录、不影响资产状态。
