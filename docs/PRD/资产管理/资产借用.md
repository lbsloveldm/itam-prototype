## 2. 需求分析

### 2.1 业务背景

企业常有临时用机、活动设备借用、备用机借用等场景，需要在不改变资产归属的前提下，将资产临时借出给员工使用，并在使用完毕后归还入库。借用流程覆盖申请、交付、用户确认、归还、入库五个阶段，且需区分硬件资产（按实例）与耗材资产（按数量）两种处理逻辑，全流程通过状态机保证台账准确。ITAM 流程类需求与 DOSM 结合实现。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **临时用机规范化**：将随意借用规范为可追踪工单，明确借用人、借出数量与归还责任。
- **库存准确**：借出/归还自动调整资产 state/substate 与库存数量，硬件按实例、耗材按数量精确核算。
- **双类型支持**：同时支持硬件（唯一实例，reserved→in use）与耗材（数量拆分/合并，新建同规格资产）。
- **闭环归还**：归还节点校验到货数量并入库，避免资产借出后无法回收。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow 的 Loaner/临时分配能力：借用资产在使用期间标记为 使用中 且 reserved for 记录借用人，归还后回到 在库/可用。ITAM 在此基础上增强了耗材类资产的数量拆分与归还新建资产逻辑，以及交付节点的多重数量校验。

### 2.3 用户故事

- 作为**员工**，我希望申请借用某规格资产并选择使用地点，以便临时获得所需设备。
- 作为**库存管理员**，我希望在交付节点选择具体资产/数量并出库，以便准确扣减库存。
- 作为**资产负责人**，我希望在归还节点确认到货数量并入库，以便资产回到可用状态。

## 3. 需求设计

### 3.1 借用流程总览

**开始 → 请求，全体员工 → 资产交付，库存管理员 → 用户确认，资产使用人 → 资产退还，资产负责人 → 库存归还，库存管理员 → End**

其中 资产 Deliver 节点「拒绝」时退回 Request 节点重新处理。

#### 3.1.1 涉及到的表

- `asset`（资产主表，硬件按实例、耗材按数量变更 state/substate/reserved for/quantity）
- `规格`（规格模型表，Request 选择 硬件+consumable 规格）
- `location` / `stockroom`（位置树与库房，交付/归还库房来源）
- `workflow_instance` / `workflow_node`（借用工单与节点自动化配置）

### 3.2 请求节点

员工选择要借用的规格（规格）与使用位置（location）。

- **选择规格操作说明**：点击 choose 规格 后弹窗展示 硬件 + consumable 所有 规格 名称；规格 页面支持多选；回显展示已选中的 规格 数据；弹窗支持搜索、排序、筛选、分页；点击确认后将选中 规格 名称回显到 DOSM。点击 ok 后至少选择一个 规格，否则提示：`Please select at least one asset 规格`；结果回显 DOSM 表单；点击 cancel 返回 DOSM。
- **位置操作说明**：多级下拉搜索单选，搜索结果高亮展示；点击 ok 后将结果回显到 DOSM 表单，展示形式为「xx》xx》xx」；二次点击展开回显已选择的地点名称；点击 cancel 返回 DOSM。数据来源于 ITAM 中的位置树。

### 3.3 资产交付节点

库存管理员根据 Request 选择的 规格 与数量，选择具体出库资产。数据来源于 Request 中选择 规格 的数据，展示字段：名称、location、Request。

#### 3.3.1 字段说明（当 规格 类型为 hardware 时）

| 字段名 | 数据类型 | 是否必填 | 是否可编辑 | 备注说明 |
| --- | --- | --- | --- | --- |
| source stockroom | 下拉搜索单选 | 是 | 是 | 下拉数据为 Request 选择的 location 关联的库房+货架+货位；无需选择最小节点；展现形式为「位置名称+位置下的数量+位置下所有的数量」，库房/货架/货位的 in stock 数量独立计算（举例：库房 5/10） |
| in stock | 数字 | - | 否 | 数据来源于所选位置下 规格 的库存量，满足：stockroom 相符、state=in stock、substate=available |
| consume quantity | 整数 | 是 | 否 | 数量由 asset tag 中选中的资产数量自动带出 |
| 已预留 for | 下拉搜索单选 | 是 | 否（只读） | 默认为工单中的 request for |
| asset | 下拉多选（名称） | 是 | 是 | 下拉数据为库房中可用的资产，满足：stockroom 相符（只展示所选位置下资产）、state=in stock、substate=available |

#### 3.3.2 字段说明（当 规格 类型为 consumable 时）

| 字段名 | 数据类型 | 是否必填 | 是否可编辑 | 备注说明 |
| --- | --- | --- | --- | --- |
| source stockroom | 下拉搜索单选 | 是 | 是 | 下拉数据为 Request 选择的 location 关联的库房+货架+货位；无需选择最小节点；展现形式为（位置下可用数量+位置下所有子位置可用数量）位置名称，例：（3/7）北京库房 |
| 资产 | 下拉搜索单选 | 是 | 是 | 下拉数据为所选库房位置下可选择的资产规格名称，满足：stockroom 相符、state=in stock、substate=available；展现形式为（可用数量）资产名称，例：（3）资产名称 |
| in stock | 数字 | - | 否 | 数据来源于所选资产的可用数量 |
| consume quantity | 整数 | 是 | 是 | 借出数量 |
| 已预留 for | 下拉搜索单选 | 是 | 否（只读） | 默认为工单中的 request for |

#### 3.3.3 操作说明与校验

- 点击 consume 后列表中新增一行；点击 delete 删除行；点击 cancel 返回 DOSM。
- 点击 submit 校验：
  - **校验1**：存在必填项，保存失败，提示 `Failed to save, required fields exist`。
  - **校验2**：单条记录中 consume 数量 不可大于 in stock 数量，提示 `The consumption quantity cannot be greater than the inventory quantity`。
  - **校验3**：每个 规格 的 consume 数量 之和必须等于 Request 数量，提示 `xxx quantity consumed is not the same as the Request quantity`。
  - **校验4**：单个消耗品资产中 consume 数量 之和不可大于资产本身数量。
  - 校验通过：将结果回显到 DOSM 表单。

#### 3.3.4 流程自动化

触发方式：名称=end of 资产 deliver，条件=工单离开节点，生效范围=部分节点，选择节点=资产 deliver，执行方式=接口调用，执行时机=立即执行。触发内容：

- **选择的 硬件 资产**：state=in stock；substate=reserved；reserved for=工单中的 reserved for。
- **选择的 consumable 资产**：
  - 若 consume quantity 与耗材本身 数量 相等：state 更改为 in stock；substate 更改为 reserved。
  - 若 consume quantity 小于耗材本身 数量：① 原 consumable 资产 数量 = 原 数量 − consume quantity；② 新建一条同规格 consumable 资产数据（规格、规格 category、stockroom、location、cost、asset tag、cost center 与原一致；数量=consume quantity；state=in stock；substate=reserved）；③ 当选择资产为多个时，新建的耗材资产数据不做合并。

### 3.4 用户确认节点

资产使用人确认收到借用资产。流程自动化：名称=end of 用户 confirmation，条件=工单离开节点，选择节点=用户 confirmation，接口调用，立即执行。触发内容：

- **审批通过**：
  - 硬件 资产：state=in use；substate=none；assign to=工单中的 reserved for；清空 stockroom。
  - consumable 资产（新建的）：state=consumed；substate=none；assign to=工单中的 reserved for；清空 stockroom。
- **审批不通过（退回）**：
  - 硬件 资产：state=in stock；substate=available；reserved for 清空。
  - consumable 资产（新建的）：state=in stock；substate=available。

### 3.5 资产退还与库存归还节点

资产负责人（资产 归还）发起归还，库存管理员（归还）接收资产入库。数据来源于 资产 return 归还的资产规格数据，单个资产为一条数据。

#### 3.5.1 字段说明（归还表格）

| 字段名 | 数据类型 | 是否必填 | 是否可编辑 | 备注说明 |
| --- | --- | --- | --- | --- |
| 借用资产名称/asset tag/借用数量 | 展示 | - | 否 | 左侧展示借用资产的名称、asset tag、借用数量 |
| Remaining 授权数 / Remaining 数量 | 数字 | - | 否 | =合计 Requested − 硬件为 授权数，耗材为 数量 |
| Receiving 数量 | 整数 | 是 | 是 | 不可大于 Remaining，硬件来源于 Capture 资产标识 选中数据；耗材默认为 合计 Requested |
| Receiving 库房 | 下拉搜索单选 | 是 | 是 | 下拉数据为库房+货架+货位，无需选择最小节点，默认为 资产 Deliver 时的库房位置（耗材为借用位置可服务的库房位置） |

#### 3.5.2 归还校验与保存

- 保存校验：① 单资产 receiving quantity 不可大于 remaining quantity，提示 `The receiving quantity cannot be greater than the remaining quantity`；② 所有资产 receiving quantity 不可均为 0，提示 `Please receive at least one asset`；③ 任一资产 receiving quantity 不为 0 时可保存。
- **保存成功后**：
  - 到货资产类型为 硬件：state=in stock；substate=available；reserve for 清空；分配给 清空；stockroom=归还时间选择的库房位置；location=库房位置。
  - 归还物料类型为 consumable：新建一条同规格 consumable 资产（规格、规格 category、stockroom、location、cost、asset tag、cost center、parent 与原一致；数量=receiving quantity；state=in stock；substate=available；分配给 清空；stockroom=归还时间选择的库房位置；location=库房位置）；多次到货仍遵从以上逻辑，在新增耗材上增加 数量 即可。

### 3.6 字段字典值说明（借用状态机）

| 阶段/字段 | 字典值 | 说明 |
| --- | --- | --- |
| 资产 Deliver 后（硬件） | state=in stock, substate=reserved, reserved for=request for | 交付后资产预留给借用人 |
| 资产 Deliver 后（consumable 相等） | state=in stock, substate=reserved | 借出量等于库存量时整条预留 |
| 资产 Deliver 后（consumable 小于） | 原资产 数量 扣减 + 新建资产 state=in stock/substate=reserved | 借出量小于库存量时拆分新建 |
| 用户 confirmation 通过（硬件） | state=in use, substate=none, assign to=reserved for | 用户确认后进入在用 |
| 用户 confirmation 通过（consumable） | state=consumed, substate=none, assign to=reserved for | 耗材确认后进入已消耗 |
| 用户 confirmation 退回（硬件） | state=in stock, substate=available, reserved for 清空 | 退回后回到可用 |
| 归还 后（硬件） | state=in stock, substate=available | 归还入库后可用 |
| 归还 后（consumable） | 新建 state=in stock, substate=available | 归还入库新建同规格耗材 |

### 3.7 页面功能与交互逻辑

- **发起入口**：借用工单从 Request 节点开始，员工选择 规格（硬件+consumable）与 location。
- **交付页**：库存管理员按 规格 类型（硬件/耗材）分别选择 source stockroom、asset/数量，遵守四项校验后 submit。
- **确认/归还**：用户确认收货触发在用；资产负责人发起归还、库存管理员按 Receiving 数量/库房 入库。
- **数量展示**：库房下拉统一以「可用数量/总数量」形式展示，库房、货架、货位独立计算。

## 4. 验收标准

- 借用流程五节点（Request→资产 Deliver→用户 confirmation→资产 归还→归还）可完整推进，资产 Deliver 可 拒绝 退回 Request。
- Request 支持 硬件+consumable 规格 多选与位置树单选，空选时提示 `Please select at least one asset 规格`。
- 资产 Deliver 四项校验（必填/单条不超库存/规格合计等于请求/耗材合计不超资产数量）生效；硬件与耗材字段与库存过滤条件符合定义。
- 交付/确认/归还各节点状态机准确：硬件 reserved→in use→归还 available；耗材按数量拆分/合并、归还新建同规格资产。
- 归还 校验（不超剩余、至少归还一个）生效，入库后 stockroom/location/assigned 等字段按定义更新。
