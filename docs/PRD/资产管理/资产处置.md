## 2. 需求分析

### 2.1 业务背景

资产退役后需进入处置流程，完成物理层面的最终处置（报废、出售、捐赠、供应商回收等），并留存处置凭证以满足财务与合规审计要求。处置流程需明确审批、取件、离场、归档等节点，并在各节点自动推进资产状态，保证台账数据与资产真实生命周期一致。ITAM 流程类需求（处置、退役、领用等）均与 DOSM 结合实现，页面数据双向回显。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **合规留痕**：处置全流程节点清晰、可追踪，处置文件归档满足审计要求。
- **状态一致性**：各节点自动推进资产 state/substate，确保台账反映资产真实处置进度。
- **风险控制**：审批节点前置，防止未经授权的资产流出；离场节点标记运输中状态，避免资产丢失。
- **成本核算**：处置结果（如转售价格、处置原因）为资产残值与 TCO 核算提供依据。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow HAM 的 资产 处置 流程：处置需经审批，资产退役后进入待处置（待处理 disposal）子状态，处置完成后 state=已退役、substate=Disposed。ITAM 在此基础上增加 计划取件与 资产离场节点，覆盖物流取件与离场过程的状态追踪。

### 2.3 用户故事

- 作为**资产管理员**，我希望选择已退役资产发起处置并经审批，以便合规地完成资产报废/出售。
- 作为**合规经理**，我希望在审批节点确认处置的合理性，以便防止资产未经授权流出。
- 作为**IT 运维**，我希望在离场与处置文件节点自动更新资产状态，以便台账实时反映处置进度。

## 3. 需求设计

### 3.1 处置流程总览

处置流程包含五个节点，整体为串行推进，审批不通过可驳回至请求节点：

**开始 → 请求，资产管理员 → 审批，合规经理 →〔通过〕→ 计划取件 → 资产离场 → 处置文件，资产管理员 → 结束**

其中 Approval 节点「驳回」时，工单退回 Request 节点重新处理。

#### 3.1.1 涉及到的表

- `asset`（资产主表，读取候选资产并变更 state/substate）
- `workflow_instance`（处置工单实例）
- `workflow_node`（工单节点与节点自动化配置）

#### 3.1.2 各节点功能与流程自动化

| 节点 | 处理角色 | 功能描述 | 流程自动化（触发内容） |
| --- | --- | --- | --- |
| 请求 | 资产管理员 | 选择待处置资产。数据来源于 ITAM 全部资产，需**同时满足**：type=hardware、state=已退役、substate=none。操作：多选至少选一个；顶部支持搜索、排序、分页；选择完成后将资产数据回显到 DOSM 中 | — |
| 审批 | 合规经理 | 对处置申请进行审批，通过后进入取件；驳回退回 Request | 触发方式：名称=Approval，条件=工单离开节点，生效范围=部分节点，选择节点=Approval，执行方式=接口调用，执行时机=立即执行。触发内容：将选择资产的 substate 更改为 **pending dispose** |
| 计划取件 | 资产管理员 | 安排处置物流取件时间与相关信息 | — |
| 资产离场 | 资产管理员 | 资产实物离开企业场地，标记运输 | 触发方式：名称=资产 departure，条件=工单离开节点，生效范围=部分节点，选择节点=资产 departure，执行方式=接口调用，执行时机=立即执行。触发内容：将选择资产的 state 更改为 **in transit**，substate 更改为 **pending dispose** |
| 处置文件 | 资产管理员 | 归档处置凭证/文件，完成处置 | 触发方式：名称=处置 Documentation，条件=工单离开节点，生效范围=部分节点，选择节点=处置 Documentation，执行方式=接口调用，执行时机=立即执行。触发内容：将选择资产的 state 更改为 **retired**，substate 更改为 **disposed** |

### 3.2 Request 节点字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 待处置资产 | 关联多选 | - | 数据来源于 ITAM 资产，筛选条件 type=hardware 且 state=已退役 且 substate=none |
| 名称 | VARCHAR | 40 | 资产显示名称，列表展示 |
| 资产标识 | VARCHAR | 40 | 资产标签，唯一标识 |
| 状态 | VARCHAR | 40 | 资产状态，候选须为 已退役 |
| 子状态 | VARCHAR | 40 | 子状态，候选须为 none |

### 3.3 字段字典值说明（处置状态机）

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| Request 候选条件 | type=hardware | 仅硬件资产可进入处置流程 |
| Request 候选条件 | state=已退役 | 处置对象须为已退役资产 |
| Request 候选条件 | substate=none | 已退役且无进行中子状态的资产 |
| Approval 后 | substate=pending dispose | 审批通过后资产进入待处置 |
| 资产 departure 后 | state=in transit, substate=pending dispose | 资产离场后进入运输中、待处置 |
| 处置 Documentation 后 | state=retired, substate=disposed | 处置文件归档后资产终态：已退役、已处置 |

### 3.4 页面功能与交互逻辑

- **发起入口**：资产台账列表选中已退役资产，在「更多/操作」中选择「处置」，进入处置工单 Request 节点。
- **Request 选择页**：展示满足条件（已退役/none/hardware）的资产，多选、至少一个；顶部支持搜索、排序、分页；确认后资产回显 DOSM 表单。
- **审批交互**：Approval 节点提供「通过/驳回」；驳回则退回 Request 节点。
- **状态联动**：各节点离开时通过接口调用自动变更资产 见 3.1.2，无需人工逐条修改。

## 4. 验收标准

- 处置流程五节点（Request→Approval→Schedule Pickup→资产 departure→处置 Documentation）可完整推进，Approval 驳回可退回 Request。
- Request 节点候选资产严格满足 type=hardware、state=已退役、substate=none，支持多选、搜索、排序、分页。
- 各节点流程自动化按定义准确变更资产状态：Approval→substate=pending dispose；资产 departure→state=in transit & substate=pending dispose；处置 Documentation→state=retired & substate=disposed。
- 处置结果在 DOSM 与 ITAM 台账双向一致回显。
