## 2. 需求分析

### 2.1 业务背景

当资产达到使用寿命末期（生命周期结束、维保到期、故障不可修复等）或不再需要时，需要将其退役下线。退役流程需经审批与技术处理，退役后自动更新资产状态、清理关联授权与维保合同的移除日期，保证台账、授权、合同数据一致。ITAM 流程类需求与 DOSM 结合实现，页面数据双向回显。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **生命周期闭环**：将资产从在用/在库规范地下线，衔接后续处置流程，形成完整生命周期。
- **数据一致性**：退役时自动清空 硬件 Entitlements、更新维保合同 removed date，避免授权与合同数据悬挂。
- **合规与审批**：退役经 IT/财务/合规多方审批，防止误退役与资产损失。
- **计划性**：支持填写计划退役时间（计划退役日期 time），便于提前规划。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow HAM 退役流程：资产进入待退役（待处理 retirement）子状态后，经技术处理正式退役（state=已退役、substate=none）。ITAM 在此基础上强化了退役对软件授权（硬件 Entitlements）与维保合同（removed date）的联动清理，并将计划退役时间统一同步到工单内所有资产。

### 2.3 用户故事

- 作为**资产管理员**，我希望选择符合条件的资产发起退役并填写计划退役时间，以便有计划地下线资产。
- 作为**IT/财务/合规经理**，我希望在审批节点确认退役合理性，以便控制退役风险。
- 作为**IT 团队**，我希望退役完成后自动清理授权与合同关联、更新退役时间，以便数据准确无需手工处理。

## 3. 需求设计

### 3.1 退役流程总览

退役流程包含三个节点，审批不通过可驳回至请求节点：

**开始 → 请求，资产管理员 → 审批：IT 经理 / 财务经理 / 合规经理 →〔通过〕→ 技术处理，IT 团队 → 结束**

其中 Approval 节点「驳回」时，工单退回 request 节点重新处理。

#### 3.1.1 涉及到的表

- `asset`（资产主表，读取候选资产并变更 state/substate、Scheduled/已退役 时间）
- `asset_entitlement`（资产-软件授权关联表，退役时清空 硬件 Entitlements）
- `contract` / `contract_asset`（维保合同及关联表，更新 removed date）
- `workflow_instance` / `workflow_node`（退役工单与节点自动化配置）

#### 3.1.2 各节点功能与流程自动化

| 节点 | 处理角色 | 功能描述 | 流程自动化（触发内容） |
| --- | --- | --- | --- |
| 请求 | 资产管理员 | 选择待退役资产并填写计划退役时间。数据来源于 ITAM 全部资产，需满足：type=hardware 且【state=in stock 且 substate ∈ {available / 已预留 / 故障 / 待维修}】或【state=in use 且 substate=none / End of support】。操作：多选至少一个；顶部支持搜索、排序、分页；选择完成后将资产数据回显到 DOSM | — |
| 审批 | IT 经理 / 财务经理 / 合规经理 | 对退役申请进行审批，通过进入技术处理；驳回退回 request | 触发方式：名称=Approval，条件=工单离开节点，生效范围=部分节点，选择节点=Approval，执行方式=接口调用，执行时机=立即执行。触发内容：① 将选择资产的 substate 更改为 **pending retirement**；② 将 Request 节点选择的 计划退役日期 time 更新至工单中所有资产的 计划退役日期 time 字段 |
| 技术处理 | IT 团队 | 执行退役技术动作并落终态 | 触发方式：名称=技术处理，条件=工单离开节点，生效范围=部分节点，选择节点=技术处理，执行方式=接口调用，执行时机=立即执行。触发内容：① state 更改为 **retired**；② substate 更改为 **none**；③ 清空所选资产下的 硬件 Entitlements；④ 处置资产关联的维保合同（contract 规格=maintain），将资产的 removed date 更新为工单通过时间；⑤ 资产表单信息更新：已退役 time = 工单通过时间 |

### 3.2 request 节点字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 待退役资产 | 关联多选 | - | 数据来源于 ITAM 资产，按 3.1.2 候选条件过滤 |
| 名称 | VARCHAR | 40 | 资产显示名称 |
| 资产标识 | VARCHAR | 40 | 资产标签，唯一标识 |
| 状态 | VARCHAR | 40 | 资产状态，候选须为 in stock / in use |
| 子状态 | VARCHAR | 40 | 子状态，按候选条件约束 |
| 计划退役日期 time | DATE | - | 计划退役时间，审批后同步至工单内所有资产 |
| 已退役 time | TIMESTAMP | - | 实际退役时间，技术处理后取工单通过时间 |

### 3.3 字段字典值说明（退役状态机）

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| request 候选条件 | type=hardware | 仅硬件资产可退役 |
| request 候选条件（在库） | state=in stock 且 substate ∈ {available / 已预留 / 故障 / 待维修} | 在库且可退役的子状态 |
| request 候选条件（在用） | state=in use 且 substate ∈ {none / End of support} | 在用且无子状态或已过维保支持 |
| Approval 后 | substate=pending retirement | 审批通过后资产进入待退役 |
| 技术处理 后 | state=retired, substate=none | 退役终态：已退役、无子状态 |
| 技术处理 联动 | 硬件 Entitlements=清空；维保合同 removed date=工单通过时间；已退役 time=工单通过时间 | 授权、合同、时间字段联动更新 |

### 3.4 页面功能与交互逻辑

- **发起入口**：资产台账列表选中符合条件资产，在「更多/操作」中选择「退役」，进入退役工单 request 节点。
- **request 选择页**：展示满足候选条件的资产，多选、至少一个；顶部搜索、排序、分页；填写计划退役时间；确认后回显 DOSM。
- **审批交互**：Approval 提供「通过/驳回」，驳回退回 request；通过时自动将 substate 置 pending retirement 并同步计划退役时间到所有资产。
- **技术处理**：技术处理 节点离开时自动完成退役终态与授权/合同/时间联动更新。

## 4. 验收标准

- 退役流程三节点（request→Approval→技术处理）可完整推进，Approval 驳回可退回 request。
- request 候选资产严格满足「type=hardware 且（在库可退子状态 或 在用 none/End of support）」，支持多选、搜索、排序、分页；计划退役时间可填写。
- Approval 通过后 substate=pending retirement，且 计划退役日期 time 同步至工单内所有资产。
- 技术处理 完成后：state=retired、substate=none、硬件 Entitlements 清空、维保合同 removed date=工单通过时间、已退役 time=工单通过时间。
