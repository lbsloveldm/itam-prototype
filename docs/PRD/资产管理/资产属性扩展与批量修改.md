## 2. 需求分析

### 2.1 业务背景

**资产属性扩展**：CMDB 与 ITAM 在属性管理上既有重叠又有根本性区别——CMDB 管理"关系"与"状态"，ITAM 管理"价值"与"生命周期"。当客户只想要 ITAM 而不引入完整 CMDB 时，需要一种方式在 ITAM 内扩展技术规格等属性，同时保持 ITAM 的核心定位。

**批量修改**：在资产管理中，有部分场景需要将大批量资产的某属性信息统一调整，因此需要设计批量修改功能，避免逐条修改的低效。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **满足客户诉求**：在不偏离 ITAM 核心的前提下，快速、低成本记录关键静态技术规格，满足资产筛选、统计与基础运维。
- **数据聚合价值**：通过集成"借用"其他系统数据，展现 ITAM 作为资产主数据平台的价值。
- **效率提升**：批量修改减少逐条操作，提升大批量属性调整的作业效率。

#### 2.2.2 调研结论及竞品分析

**CMDB 与 ITAM 属性核心区别**：
- CMDB 管理"关系"与"状态"，回答"它如何影响业务服务？"（如实时 CPU 使用率、承载哪个应用数据库等动态运行状态与逻辑关系）。
- ITAM 管理"价值"与"生命周期"，回答"它花费了多少？归谁所有？"（如型号、序列号、采购、成本、责任人等核心标识信息）。

参考 ServiceNow：批量更新（Update All / Batch）对筛选结果集统一赋值；属性扩展通过 规格/class 字段扩展或集成发现工具同步。

### 2.3 用户故事

- 作为**资产管理员**，我希望在资产卡片中记录操作系统、内存、CPU、硬盘、IP 等关键静态技术规格，以便进行资产筛选、统计和基础运维。
- 作为**IT 运维**，我希望将其他系统（vCenter、Zabbix、Lansweeper 等）的技术属性同步到 ITAM，以便获得统一资产视图。
- 作为**资产管理员**，我希望勾选多个资产后批量修改某些属性并设置新值，以便高效完成大批量调整。

## 3. 需求设计

### 3.1 资产属性扩展

#### 3.1.1 CMDB 与 ITAM 属性区分对比

| 维度 | CMDB | ITAM |
| --- | --- | --- |
| 管理核心 | "关系"与"状态" | "价值"与"生命周期" |
| 回答的问题 | 它如何影响业务服务？ | 它花费了多少？归谁所有？ |
| 典型属性 | 运行状态（实时 CPU 使用率）、逻辑关系（承载的应用/数据库）、依赖关系 | 型号、序列号、采购、成本、折旧、责任人、合同 |
| 动态性 | 动态运行状态与关系 | 相对静态的标识与财务信息 |

#### 3.1.2 方案一：ITAM 产品内"轻量级"实现（首选推荐）

在不引入完整 CMDB 概念的情况下，扩展 ITAM 的属性字段。在服务器等资产模型中添加"技术规格"属性组：

| 属性字段 | 示例 | 备注 |
| --- | --- | --- |
| 操作系统 | Windows 服务器 2019、Linux CentOS 7.9 | 相对静态，生命周期内很少改变 |
| 内存容量 | 单位：GB | 相对静态 |
| CPU 型号与核数 | Intel Xeon Gold 6248, 32 Cores | 相对静态 |
| 硬盘大小与类型 | 2TB SAS、1TB SSD | 相对静态 |
| IP 地址 | 主管理 IP | 相对静态 |

- **客户话术**：可在资产卡片中记录这些关键的、静态的技术规格，属于资产的核心标识信息（如同型号和序列号），有助于资产筛选、统计和基础运维。
- **划定边界**：不管理动态运行状态（如实时 CPU 使用率）或与其他设备的逻辑关系（如承载哪个应用数据库），那些是运维监控工具和 CMDB 的范畴。
- **优点**：快速、低成本、满足客户大部分表面需求，不偏离 ITAM 核心。

#### 3.1.3 方案二：通过集成"借用"数据（专业推荐）

若客户已有其他系统存在这些数据，集成是最优雅的方式。

| 环节 | 说明 |
| --- | --- |
| 识别数据源 | 自动化发现工具（Lansweeper、PDQ Inventory）；监控工具（Zabbix、Prometheus、Nagios）；云平台 API（AWS、Azure、VMware vCenter）；现有简易 CMDB 或 Excel |
| 实现方式 | 通过 API、脚本或中间件，定期将来自这些数据源的"内存""操作系统"等信息同步到 ITAM 对应资产记录上；界面中字段可显示为"来自 vCenter"并标记同步时间 |
| 定位与话术 | ITAM 作为统一资产"主数据"平台，通过集成把其他专业工具已有的技术属性"拉"过来，提供统一资产视图（财务信息 + 关键技术属性） |
| 优点 | 数据自动更新、准确度高，展现 ITAM 作为数据聚合平台的价值 |

#### 3.1.4 方案三：提供轻量级发现功能（进阶方案，仅供了解）

| 环节 | 说明 |
| --- | --- |
| 实现方式 | 开发或集成一个简单的 Agent 或基于凭证的扫描脚本，定期扫描服务器收集"技术规格"信息 |
| 本质 | 功能阉割版 CMDB，只收集静态配置项，不处理关系和依赖 |
| 优点 | 数据自动化，控制力强 |
| 缺点 | 开发成本高，容易滑向 CMDB 赛道，导致产品定位模糊 |

### 3.2 台账批量修改某些属性信息（Batch Modification）

#### 3.2.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 批量修改资产属性 | 筛选目标资产，对某些属性统一设置新值 | 对于"所有资产（All assets）"不提供批量修改功能（当前已有功能）；筛选并勾选目标资产后可批量修改 |
| 批量修改入口 | 勾选资产后显示按钮 | A1. 有资产被勾选后，显示"批量修改（Batch Modification）"按钮 |
| 修改弹窗 | 选择属性并设置新值 | A2. 点击批量修改后，进入修改属性选择及设置新值页面，在当前页弹窗展示；A3. 展示选中的资产数量，可选择资产台账的所有资产类别对象，展示的属性为该类别中可修改的属性 |
| 库房 在库校验 | 硬件 库房 批量修改受在库约束 | A4. 对硬件资产，库房 属性可展示在可改属性中，仅当所选资产全部在库才可修改成功，否则全部修改失败，提示"修改失败！您要修改的资产存在部分不在库房的情况，仅支持对在库资产修改库房"（英文见下） |
| 多属性修改 | 支持多选、修改多个属性 | 修改页面不用 CMDB 方式，支持多选，修改多个属性；仅对列出的场景字段做修改 |
| 确认与结果 | 确认修改后提示成功 | 点击"确认修改（确认 Changes）"后，提示修改成功（用当前现有系统提示）；被修改资产属性查看时全部展示设置的新值 |

### 3.3 页面功能与交互逻辑

#### 3.3.1 属性扩展

- 在资产 规格 / Class 中扩展技术规格属性组（操作系统、内存容量、CPU 型号与核数、硬盘大小与类型、IP 地址等）。
- 集成场景下字段可标注数据来源（如"来自 vCenter"）并显示同步时间。

#### 3.3.2 批量修改

- **入口**：资产台账列表页，勾选资产后显示"批量修改（Batch Modification）"按钮；All assets 不提供批量修改。
- **弹窗**：当前页弹窗展示，显示选中资产数量、选择要修改的属性、设置新值。
- **属性范围**：按资产类别展示该类别可修改属性（见 3.2.2 矩阵）。
- **校验**：硬件 库房 修改需所选资产全部在库，否则全部失败并提示。
- **确认**：点击"确认修改"后提示成功，查看资产属性全部展示新值。

## 4. 验收标准

- 属性扩展方案清晰区分 CMDB 与 ITAM 属性边界；可在资产模型中扩展技术规格属性组（操作系统/内存/CPU/硬盘/IP 等）。
- 集成"借用"数据方案可将外部系统技术属性同步到 ITAM 并标注来源与同步时间（依赖集成/映射能力）。
- 批量修改：勾选资产后显示"批量修改（Batch Modification）"按钮；All assets 不提供批量修改。
- 批量修改弹窗展示选中资产数量、可选属性（按类别）、设置新值；支持多选多属性修改。
- 可批量修改属性矩阵生效：硬件/耗材、硬件/耗材/捆绑/软件、硬件/软件、硬件/耗材/捆绑/软件。
- 硬件 库房 批量修改：全部在库才成功，存在不在库时全部失败并给出准确中英文提示。
- 确认修改后提示成功，被修改资产查看时全部展示设置的新值。
