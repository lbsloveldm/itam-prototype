## 2. 需求分析

### 2.1 业务背景

当企业建立了规格模型后，需要对与规格对应的实物资产进行创建与管理。捆绑资产（资产包）是一组资产的集合，包括消耗性资产、硬件资产、软件。只有处于"库存"（在库）状态且"可用"（可用）子状态的资产才能被添加到资产包中；资产包中的资产不能作为单个资产使用。可以从库存中现有资产创建资产包，作为单一实体来跟踪、预留或部署一组资产，简化管理流程，尤其适用于将多个资产作为整体操作的场景。

捆绑规格（捆绑 规格）由其他独立 规格 组合而成，可以是抽象的（捆绑对象中有些本身就是集合形式）或具体的（所有捆绑对象都是单独的 asset）。抽象规格包被创建为容器，其中一个资产被定义为主要组件；规格 category 定义了可以在捆绑包中包含哪些资产以及主要组件。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **资产价值跟踪**：跟踪资产生命周期流转对企业财务管理的影响，围绕财务价值管理诉求，联动合同、费用/成本、厂商/组织、运营管理。
- **整体化管理**：将多个资产作为单一实体跟踪、预留、部署、分配、退役，简化管理流程。
- **退役优化**：通过退役资产包集中管理不再需要的资产，识别可重新分配/维修/再利用的资产，减少浪费、降低成本，确保财务记录准确。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow 捆绑：捆绑规格通过 `cmdb_m2m_model_component` 多对多关系表存储规格绑定组件；组件区分主要组件与 Mandatory/选填 参数；捆绑资产分配/退役以根节点为操作入口，子资产状态跟随根节点变化。

### 2.3 用户故事

- 作为**规格管理员**，我希望创建捆绑规格并添加组件（含主要组件、强制/可选参数），以便定义资产包的组成。
- 作为**资产管理员**，我希望将资产包整体分配给用户，包内子资产同步分配，以便一次性完成整组资产的分配。
- 作为**资产管理员**，我希望将资产包整体退役（先释放子资产），以便集中管理不再需要的资产。

#### 3.1.4 创建 捆绑 规格 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 创建 捆绑 Models | 为资产创建捆绑 规格，将 bundle 挂在 bundle category 下 | 规格分类 写死为 捆绑；名称 由系统按规则生成（新增页不显示）；入口：Bundled models 列表页右侧新增入口，点击 "New" 进入 Create 捆绑 规格 页，填写字段后点击 "提交" 新增成功，列表页第一条为最新记录；点击 "cancel" 新增失败，列表页无新增数据 |
| 列表页搜索 | 支持模糊搜索 | 支持按 名称、CI class、名称、规格编号、制造商 模糊搜索；名称 所在下拉框选项为 5 个搜索条件；输入关键词回车后搜索，结果页展示与列表页相同；结果为空时不显示数据；默认显示 规格分类 字段，CI class 挂在 规格 category 后显示对应名称，无值显示为空 |

| 删除 Bundled 规格 | 可对未实例化的捆绑 规格 删除 | 点击列表页 名称 进入详情页，可删除并提交；仅当该规格下无实例化数据时 删除 可点击；有实例化数据时 删除 置灰；删除成功后列表页不再显示该 规格 |

- **制造商**：下拉选项，显示生产厂商名，由数据字典维护。
- **CI class**：下拉选项，由 CMDB 数据字典提供。
- **规格 Categories**：当前已有的 category 列表。
- **归属人**：下拉选项，从 globe 人员中筛选。
- **状态**：固定选项 Build、In Production、已退役、Sold、None。
- **获取方式**：固定选项 Both、Buy、租赁、None。
- **支出类型**：固定选项 Capex、Opex、None。
- **成本**：货币，输入，小数部分不超过 4 位否则四舍五入。
- **Depreciation**：折旧，固定选项，可数据字典维护。
- 多项字段为下拉选项且支持模糊搜索。

### 3.3 分配资产包（Allocate 捆绑 资产）

#### 3.3.1 角色

- 角色要求：资产。

#### 3.3.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 分配资产包 | 将资产包整体分配给用户，包内子资产同步分配给同一用户 | 分配根节点资产包，触发所有归属同一根节点的子资产同步分配；可分配条件见下 |
| 可分配条件 | 资产 condition 满足 | A. 状态=在库 & 子状态=可用；B. 状态=在库 & 子状态=已预留 & （已预留 for 为空 或 已预留 for 与 分配给 值相同） |
| 分配给 默认值 | 预留资产分配默认值 | 当资产（硬件/软件/消耗品/捆绑）子状态=已预留 且 已预留 for 有值，将 分配给 指派给某人时，取 已预留 for 值赋给 分配给 作为默认值 |
| 分配入口 | 仅根节点可分配（0312 更改方案） | 分配入口仅放在根节点（Bundled Asset1），其余子资产不可分配；捆绑包/资产作为非独立资产时进入详情页不可修改 state、substate、分配给、置灰；根节点详情页显示 "Allocate"，点击进行分配 |
| 分配结果 | 树形结构同步分配 | 点击 OK 后弹出分配成功提示，树形结构展示所有已成功分配的资产；硬件、捆绑 状态=使用中、子状态 为空；耗材 状态=已消耗、子状态 为空 |

> 分配根节点的两个条件（0312）：A. 捆绑包根节点资产 状态=在库 & 子状态=可用；B. 子资产 状态=在库 & 子状态=已预留 & （已预留 for 为空 或 已预留 for 与 分配给 值相同）。

### 3.4 退役资产包（Retire 捆绑 资产）

#### 3.4.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| Retire 资产包 | 将资产包整体进行 Retire | 退役前需先 Release 关联的 component 子资产；Release 遵循现有系统逻辑 |
| Retire 入口 | 仅根节点可退役 | A. Retire 仅在 捆绑 资产根节点存在，子资产不可退役；B. 捆绑包/资产作为非独立资产时详情页不可修改 state、substate、置灰；C. 根节点详情页显示 "Retire"，可退役条件：1）状态=（维护中 或 在库）& 子状态=待维修 时出现 也是出现 Release 的条件；2）仅当 Release 执行完之后才可 Retire |
| Release 释放资产 | 释放关联子资产 | 硬件资产释放后变为可分配独立资产，状态=在库、子状态=可用；消耗品资产释放后，若当时被分配的规格在原位置且状态为 in stock，则实体记录被删除，数量加回原消耗性资产；嵌套 捆绑 及其下子资产不释放，分配给 不变、状态与根节点相同；资产包状态变化时，仍在其中关联的子资产状态跟随资产包变化且保持相同 |
| Retire 提示 | 点击 Retire 弹窗提示 | 若有关联未释放资产：提示 "You cannot retire this bundle asset, you must release it first."；若已无关联资产：选择子状态，点击 OK 退役成功，提示 "成功! You have already retired this bundle asset."；退役后资产包 状态=已退役、子状态=用户选择的子状态，component 列表为空 |

#### 3.4.2 关联 页签（Component）

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| Component 关联页 | 捆绑 资产包显示关联 页签 页 Component | 显示已被关联捆绑的子资产 |
| 树形结构展示 | Details 页通过树形结构展示关联资产 | 树形结构显示关联资产，当前资产需高亮；有 父级 关系的资产也展示树形结构；完全独立资产的树形结构仅展示该资产本身 |
| 释放资产 | 展示改为 "Release" | 关联 页签 页 component 显示已捆绑子资产，可持续下钻；规格分类 of component、规格 of component、组件参数、Component 资产 字段及值与 Details 页完全相同，且四个字段均可点击；More 中仅导出可用，删除及导入不展示 |

## 4. 验收标准

- 捆绑规格 捆绑 规格 可创建/修改/删除，规格分类 写死为 捆绑；未实例化时可编辑/删除，已实例化时 提交/删除 置灰。
- 列表页搜索（名称/CI class/名称/规格编号/制造商）可用，结果为空时不显示数据。
- 可为 捆绑 规格 添加组件（主要组件、组件参数=Mandatory/选填），未实例化前可移除组件。
- 分配资产包：仅根节点可分配，满足 在库+可用 或 已预留 条件；分配后子资产同步分配（硬件/捆绑 使用中、耗材 已消耗），已预留 for 赋值 分配给 默认值生效。
