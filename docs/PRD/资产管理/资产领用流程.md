## 2. 需求分析

### 2.1 业务背景

ITAM 流程类需求（领用、调拨、采购、到货等）均采取与 DOSM 结合实现，在 PRD 中定义双方数据参数对接与交互形式。资产领用是员工获取资产的核心业务流程，需要覆盖硬件、软件、捆绑、消耗品四类资产规格，并通过审批、资产寻源、资产分配、用户确认等节点，保证资产分配的授权合规、库存准确与用户体验。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **成本控制**：领用前经直属领导审批，减少资产滥用；直属领导比资产管理员更了解申领人实际需求。
- **责任归属清晰**：直属领导审批代表确认授权，后续资产损坏/丢失可追责。
- **预算归属确认**：确保资产申请符合业务部门项目预算。
- **提升用户体验 + 权限隔离**：将资产寻源独立为子流程，只对用户展示业务信息（不暴露库存、供应商、渠道等敏感信息），寻源工单仅开放给资产经理。
- **多规格统一**：软件/硬件/捆绑/消耗品使用一个领用流程，用户路径短。

#### 2.2.2 调研结论及竞品分析

- **多规格方案选型**：方案1（四类资产共用一个领用流程）用户路径短，被选用；方案2（四个独立流程）扩展性强但操作路径长；方案3（一个主流程+四个子流程）可模拟购物车但存在关联工单信息传递断层且开发周期长。**结论：选择方案1**。
- **关联调整**：规格 管理中的 Publish to catalog 按钮暂时隐藏；原 Request 流程（推送 DOSM 数据表并发布服务目录）保留但不作为内置流程发版，待 DOSM 完成购物车机制后再处理。

### 2.3 用户故事

- 作为**资产经理**，我期望用户发起资产领用后由其直属领导初步审核，以减少资源滥用、资产归属不清。
- 作为**用户**，我只希望尽快知晓分配的资产并确认，不关注仓库、渠道等信息，以专注业务需求。
- 作为**资产经理**，我期望避免向用户暴露不必要的库存、供应商、渠道信息，确保权限隔离。

## 3. 需求设计

### 3.1 流程总览

**主流程**：开始 → 请求（员工）→ 审批（员工上级）→〔驳回退回请求〕→ 资产寻源（资产经理，子流程）→ 资产分配（库存管理员）→ 用户确认（员工）→〔驳回退回资产分配〕→ 确认 → 结束。

**资产寻源子流程**：开始 → 请求 → 资产寻源（资产经理）→ 分支：① 库房调拨 → 调拨流程（库存管理员）；② 本地领用；③ 供应商采购 → 采购流程（采购经理）→ 结束。

流程中增加汇报对象字段，默认为领用人的汇报对象，数据来源于 DOUC。

#### 3.1.1 涉及到的表

- `asset`（资产主表，寻源筛选与分配后变更 substate/reserved for/分配给/数量）
- `asset_model`（资产规格表，注册 hardware models 部分字段到 DOSM，数据表编码 asset_model）
- `location` / `stockroom`（位置与库房，寻源可服务库房计算）
- `software_license` / `metric_attribute` / `license_metric`（软件领用授权与分配类型）
- `bundle` / `bundle_component`（捆绑资产与子组件，逐层创建与组装）

### 3.2 前置准备（与 DOSM 交互）

- ITAM 将 hardware models 部分字段注册到 DOSM 数据表：数据表名称=资产规格，数据表编码=`asset_model`；同步机制=手动触发；数据推送时流程模版数据默认为空；使用数据表默认列表视图并带出价格、厂商、金额等字段。
- 在流程管理 » 高级设置 » 表单模版设置中，单个规格设置一个表单模版；在服务目录中将单个表单模版发布为单个服务项；在服务目录发起请求后，表单自动带出规格名称。

### 3.3 领用需求提交（location 选择）

- DOSM 表单提供标准插入组件（字段+按钮），点击按钮进入 location 选择页面（由 ITAM 提供）。
- 操作说明：数据来源于 ITAM 的 location 全量数据；顶部支持按名称精准搜索；支持选中任一节点；仅支持单选；点击 cancel 隐藏弹窗；点击 submit 将选中 location 回填到 DOSM 表单。

### 3.4 资产寻源（卡片 + 表格）

资产寻源根据 DOSM 传递的 位置、资产 规格、数量、流程发起人进行出参。

- **卡片说明**（从左往右卡片1/2/3）：
  - 卡片1：资产规格的基础数据。
  - 卡片2：固定字段 `To be sourced` + 动态数字（领用单据中资产规格待领取的数量 数量）。
  - 卡片3：固定字段 `本地库存` + 动态数字 + 操作按钮（consume）。动态数字取数逻辑：根据 stockroom 管理中每个库房覆盖的服务地址范围，用 DOSM 传递的 location 在 ITAM 中反向找到所有可服务库房；再对卡片1规格搜索关联资产实例，同时满足 state=in stock、substate=available、stockroom 在可服务库房范围内的数据汇总。
- 其他说明：初始态仅显示卡片，无表格；表格顶部固定字段 `local Order（x）`，x 代表表格内新增记录条数；表格无需分页。
- 寻源提交后向 DOSM 传递：资产 models、local stockroom、consume quantity、personnel。

### 3.5 绑定资产（Choose asset / 资产交付更改逻辑，214）

绑定资产页面用于将寻源结果绑定到具体资产实例。

#### 3.5.1 表格字段说明

| 字段名 | 字段类型 | 是否可编辑 | 是否必填 | 说明 |
| --- | --- | --- | --- | --- |
| 来源 stockroom | 下拉搜索单选 | 是 | 是 | 数据来源于 location 下关联可服务的库房名称；按库存数量从大到小排序；默认选中第一个；单一库房+单个领用人仅可创建一条记录 |
| in stock | 自动带出 | 否 | - | source stockroom 下选中库房中满足条件的资产数量 |
| Consume 数量 | 正整数 | 是 | 是 | 默认 1；不可大于 来源 stockroom 库房 in stock 数量（超出输入框标红，提示 `The quantity entered cannot exceed the inventory quantity`）；与其他库房填写数量之和不可大于 超出提示 `The number of entries cannot exceed the required quantity` |
| 已预留 for | 下拉搜索单选 | 是 | 是 | 下拉数据为 DOUC 的人员数据 |
| 资产标识 | 下拉搜索多选 | 是 | 是 | 下拉数据为 source stockroom 下满足条件资产的 asset tag；选择数量为 consume 数量 数量 |

#### 3.5.2 操作说明

- consume：默认展示一条空数据，不可删除；点击即在表格中新增一条记录。
- delete：单条记录右侧支持单个删除；最后一条记录不可删除，删除按钮置灰。
- submit 校验：单个资产规格的 Consume 数量 之和等于 To be sourced；小于失败提示 `The number of claims cannot be less than the required amount`，大于失败提示 `The number of claims cannot be more than the required amount`；必填项未填提示 `There are unfilled items`。校验通过后提交成功并关闭页面，结果回填 DOSM。
- cancel：返回上一级页面。
- 需将资产寻源时 local order 单据中选中的数据填充到绑定资产页面。

### 3.6 流程结束/资产分配自动化

- **绑定资产流程结束自动化（确认 assigned asset）**：触发方式名称=确认 assigned asset，条件=工单离开节点，生效范围=部分节点，选择节点=确认 assigned asset，接口调用，立即执行。触发内容：资产寻源结果中选中的调拨资产，当资产 state=in stock 时，将 substate 由 available 更改为 **reserved**，reserved for 由空变更为资产寻源中的 personnel。
- **补充逻辑**：当手动变更资产 state 为 in use 时，分配给 由空变更为 reserved for 的 personnel。

### 3.7 交付节点校验逻辑（609）

**前端校验（点击提交前，选择时）**：

- 硬件/消耗品/捆绑：单个规格下同一资产不可重复授权给同一用户；同一资产不可在两条记录中被选中，已选择的资产置灰不可选；库房选择不做校验。
- 软件：单个规格下已选择的软件实例不可授权给同一用户/设备。

**点击提交时校验**：

- 硬件/消耗品/捆绑/软件：消耗数量输入框不可大于库存量/可用数量。
- 硬件/消耗品/捆绑：资产标识 选择数量必须等于消耗数量，否则 asset tag 输入框标红并提示 `Insufficient number of assets`，点击确认后输入框抖动。
- 必填项未填写：保存失败提示 `Failed to save, required fields exist`，点击确认后输入框抖动。

**后端校验**：

- 硬件/软件/捆绑/消耗品：校验单个规格下的消耗/分配数量总和等于请求数量；小于提示 `xxx asset mode delivery quantity cannot be less than the requested quantity`；大于提示 `xxx asset mode delivery quantity cannot be more than the requested quantity`。
- 软件：校验分配的 software license 是否符合软件分配的设备/人员范围，不符合提示 `xx cannot be 分配给 yy`（xx=software license 名称，yy=分配给的设备/人员）。
- 校验展示：一次性提示所有失败原因，多条时使用多个 toast 提示框。

### 3.10 遗留问题与解决方案（V1.6 / V2.8）

- 寻源时单个库房可将资产分配给多个领用人，为多条记录。
- 当前资产规格与供应商无关联，寻源时供应商为全部，仅显示供应商字段（不带价格），out of stock 均展示为 false。
- 到货时 unit cost 由自动带出改为手动填写。
- 批量创建资产的成功与否，当前 DOSM 不支持交互展示，通过悬浮文字提示。
- 提前创建但未到货资产的删除触发：前置为用户已点击「提前创建资产」；节点类型为工单回退/取回/关闭/删除；节点为确认采购、设备到货。

## 4. 验收标准

- 领用主流程（请求→审批→资产寻源→资产分配→用户确认→确认）可完整推进，审批驳回退回请求、用户确认驳回退回资产分配。
- 资产寻源子流程三分支（本地领用/库房调拨/采购）可用；寻源卡片 To be sourced、本地库存 取数与可服务库房逻辑正确。
- 绑定资产表格字段与校验（Consume 数量 合计=To be sourced、不超库存、资产标识 数量=消耗数量）生效；结果回填 DOSM。
- 流程结束自动化 确认 assigned asset 将资产 substate available→reserved、reserved for 置为 personnel；置 in use 后 分配给 生效。
- 支持硬件/软件/捆绑/消耗品四类共用一个流程；软件分配校验设备/人员范围；交付回显 数量 规则正确。
