## 2. 需求分析

### 2.1 业务背景

在软件资产管理中，降级权利（Downgrade rights）满足使用灵活性（适应不同需求、应对新版本漏洞回退）、软件质量保证（回退机制）、许可证合规性（明确授权范围、方便许可管理）与软件资产有效管理（优化配置、支持升级策略）。升降级权利在 规格 层为理论规则，实例的维护状态（Maintenance）是执行开关，授权记录的采购细节才是权利来源。系统需管理升降级关系、实例继承、维护状态约束，并使合规计算与补救正确处理版本升降级。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **灵活性与风险控制**：支持降级回退，规避新版本风险，保障业务连续。
- **合规准确**：高版本授权可满足低版本使用，合规计算按 Upgrade 根节点统一核算。
- **采购/申请对齐**：补救时支持选择新版本规格采购/申请。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow SAM 的 软件 规格 Upgrade & Downgrade 对象与 软件 Assurance 维护约束：规格 预定义权利规则，实例维护状态决定是否可行使，授权记录为权利来源。本方案对齐并明确合规根节点计算。

### 2.3 用户故事

- 作为**规格管理员**，我希望 DMAP 配置的升降级关系自动同步到 规格 的 Downgrade/Upgrade 授权数 页卡。
- 作为**软件资产管理员**，我希望实例按维护状态与有效期继承并行使升降级权利。
- 作为**合规负责人**，我希望未找到实例的 规格 按 Upgrade 根节点统一计算合规。

## 3. 需求设计

### 3.1 Downgrade / Upgrade 授权数 来源与生成

#### 3.1.1 涉及到的表

- `cmdb_software_product_model`（软件规格，含 发现映射、next 版本 引用）
- `software_model_upgrade_downgrade`（软件规格升降级关系对象）
- `software_license`（软件实例，含 类型、有效期、软件 Upgrade and Downgrades 页卡数据）
- `discovery_map`（DMAP，配置升降级关系）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| DMAP 生成 Downgrade 授权数 | 规格 的 发现映射 引用的 DMAP 有关联 Downgrade rights 值时自动生成记录 | 在该 规格 关联 Downgrade 下自动新增被引用 软件规格 记录；将关系链上所有 DMAP 关联的 软件规格 展示在 Downgrade 授权数 下 |
| 页卡改名 | 现有系统 规格 关联页卡 Downgrade 改名"Downgrade 授权数" | 不显示 开始日期、结束日期 字段；Upgrade 改名"Upgrade 授权数"，记录含 upgrade parent |
| 实例继承 | 含升降级数据的 规格 被实例引用后，实例继承 规格 的升降级数据 | 实例 类型 选择包含维护、且实例处于有效期时，实例 软件 Upgrade and Downgrades 页继承 规格 的 downgrade rights 数据 |
| PPN/DMAP 生成（hold） | 依据 PPN 中 DMAP 生成 Downgrade 授权数 | hold：当前软件实例创建无 PPN 字段，暂不加 |

#### 3.1.3 升降级关系示例（关系链传递）

| 规格 | Downgrade 授权数 记录 | Upgrade 授权数（upgrade parent）记录 |
| --- | --- | --- |
| software model1 | 显示其下级降级记录 | 无 |
| software model2 | 包含 software model3 | upgrade parent = software model1 |
| software model3 | 无 | upgrade parent = software model1、software model2（两条） |

### 3.2 软件实例 类型 与维护状态约束

#### 3.2.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 实例新增 类型 字段 | 创建软件实例时新增 类型 字段 | 字典值：永久、订阅、Upgrade、永久+Maintenance、Maintenance |
| 行使权利前提 | 实例须有有效维护合约才可行使升降级 | 即使 规格 有升降级数据，实例无有效维护（如 SA）则不可行使；类型 为 永久+Maintenance 或 Maintenance 且实例未到期时，若 规格 有升降级数据，实例才可行使升降级权利 |
| 实例自动更新 | 关联 规格 的 next 版本 有值时自动更新实例 | 当 规格 X 的 next 版本 = 规格 Y，且实例 类型 为 {永久+Maintenance ｜ Maintenance} 且实例处于有效期，则实例引用的 软件规格 由 X→Y 自动更新；名称 同步更新为 asset tag + 最新 软件规格 |

#### 3.2.2 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 类型 | Choice | 40 | 软件实例许可类型，见字典 |
| next 版本 | 引用 | 32 | 软件规格下一版本，用于触发实例自动更新 |
| upgrade parent | 引用 | 32 | 升级根节点规格，合规计算追溯用 |

#### 3.2.3 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 类型 | 永久 | 永久许可 |
| 类型 | 订阅 | 订阅许可 |
| 类型 | Upgrade | 升级许可 |
| 类型 | 永久+Maintenance | 永久+维护，可行使升降级权利（实例未到期时） |
| 类型 | Maintenance | 维护，可行使升降级权利（实例未到期时） |

> 权利关系概括：规格 预定义权利规则=理论可能；实例维护状态（类型 含 Maintenance）=执行开关；授权（Entitlement）采购记录=权利来源。

### 3.3 合规计算与补救影响

#### 3.3.1 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 有实例时合规 | 规格 找到引用自己的台账实例，合规逻辑不变 | 保持原有合规计算 |
| 无实例时按根节点 | 规格 未找到引用自己的实例时，追溯 升级父级规格 根节点 | 查 软件 规格 Upgrade & Downgrade 对象，找 规格 对应的 升级父级规格 根节点（如 model3 根节点为 model1） |
| 根节点实例统计 | 统计根节点对应有效期实例数据 | 统计 software model1 对应有效期内、且 类型 含 Maintenance 或 永久+Maintenance 的实例数据总量 |
| 合规判定 | 对比 规格 实际消耗与根节点有效期实例数据 | 判断合规性；默认条件：支持升级时台账实例自动更新为最新 软件规格，保证高版本 许可证 授权满足低版本使用 |
| 安装/访问补救-采购 | 采购流程支持选择新版本采购 | 查 软件 规格 Upgrade & Downgrade 对象，取当前 规格 及其 upgrade parent 作为采购规格选项 |
| 安装/访问补救-申请 | 申请 许可证 流程支持选择新版本申请 | 取当前 规格 及其 upgrade parent 对应的实例作为申请选项 |

### 3.4 页面功能与交互逻辑

- **软件规格详情页**：Downgrade 页卡改名"Downgrade 授权数"（不显示 Start/结束日期），Upgrade 页卡改名"Upgrade 授权数"（含 upgrade parent 记录）；DMAP 关联时自动生成升降级记录并沿关系链展示。
- **软件实例详情页**：新增 类型 字段（5 个字典值）；软件 Upgrade and Downgrades 页卡在 类型 含维护且有效期内继承 规格 升降级数据；规格 有 next 版本 时按条件自动更新实例引用与 名称。
- **合规计算/补救**：无实例 规格 追溯根节点统计有效期维护类实例；采购/申请流程提供当前 规格 及 upgrade parent 版本选项。

## 4. 验收标准

- 规格 的 Downgrade/Upgrade 页卡正确改名，DMAP 关联时自动生成升降级记录并沿关系链传递（model3 的 upgrade parent 含 model1、model2 两条）。
- 软件实例新增 类型（永久/订阅/Upgrade/永久+Maintenance/Maintenance）；仅 类型 含 Maintenance 且未到期时可行使升降级权利并继承 规格 数据。
- 实例在 next 版本 有值且 类型 含维护、处于有效期时自动更新引用规格（X→Y）与 名称。
- 合规计算：有实例按原逻辑；无实例按 升级父级规格 根节点统计有效期维护类实例并判定合规。
- 补救：采购/申请流程可选择当前 规格 及 upgrade parent 新版本规格/实例。
