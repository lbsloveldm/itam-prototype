## 2. 需求分析

### 2.1 业务背景

软件安装记录和管理软件安装信息，是企业实现 IT 治理、成本优化和风险控制的核心环节。

- **核心价值 1（合规规避风险）**：通过追踪所有软件安装实例，确保实际使用量不超过购买的许可证数量，规避因违反授权协议导致的罚款或法律诉讼。例如：发现某部门安装 200 份 Adobe 软件但仅购买 150 份许可证，触发采购或卸载流程；检测虚拟机中未授权的 Oracle 数据库安装及时整改。
- **核心价值 2（成本优化）**：识别未使用的软件安装和冗余许可证，重新分配或终止订阅节省成本。例如：通过 最后使用时间 字段发现 50 台设备超过 1 年未使用某设计软件，回收许可证；分析云环境许可使用效率，将闲置 AWS 实例关联软件降级配置。

**数据录入方式**：通过自动化发现工具（SCCM）和脚本接口（如 SAMPInstallUtils 类），每日自动扫描或批量导入同步软件安装数据；**不支持人工录入**，避免产生错误。

**本期范围界定**：本期只完成 software installation 的管理，暂不对接采集工具结果（以演示数据导入为准）。对于不同时段收集到的数据，若字段值不同，可用最新数据覆盖老数据。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **合规基础数据**：为软件安装合规计算（超装判定）提供设备、用户、版本等基础事实。
- **成本洞察**：结合使用数据识别闲置安装，支撑许可证回收与降级决策。
- **数据可信**：仅接受采集/导入，禁止人工新增，保证数据来源可靠。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow：软件安装记录由 Discovery 工具/第三方集成采集；本方案与其差异在于——发现规格 引用自建发现映射表的 而非 CI 引用；安装位置 引用资产（而非 CI）；实例密钥、Entitlement 等字段不使用（样例数据均为空）。

### 2.3 用户故事

- 作为**软件资产管理员**，我希望查看采集到的软件安装明细，以便掌握每台设备上的软件安装情况。
- 作为**软件资产管理员**，我希望在自动发现识别不准确时手动修正安装记录，以便保证合规计算准确。
- 作为**合规专员**，我希望软件安装数据关联硬件资产和用户，以便判断安装是否超出授权。

## 3. 需求设计

### 3.1 软件安装表

#### 3.1.1 涉及到的表

- `cmdb_sam_sw_install`（软件安装表，含演示数据 `cmdb_sam_sw_install-2.xlsx`）
- `discovery_map`（发现规格 引用其 软件名称）
- `hardware_asset`（安装位置 / 分配给 引用资产台账）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 创建 软件 Installation 表及演示数据 | 定义软件安装记录表 | 基于要求字段建表并导入演示数据；不同时段数据字段值不同的，可用最新数据覆盖老数据 |
| 数据来源 | 通过采集软件填入 | 自动采集数据不完整/不准确时，用户可手动修正 |
| 入口调整 | 将两个入口调整放在 许可证 Management 下 | 在 许可证 Management 下增加 软件 Installation |
| 列表页无新增 | 列表页无新增按钮 | 不提供人工新增软件安装记录功能，仅可修改采集到的数据 |
| 详情页无删除 | 编辑软件记录详情页不显示删除按钮 | — |

#### 3.1.3 字段说明（A. 基础字段）

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 名称 | 字符串 | 255 | 软件安装的显示名称（如 Microsoft Office 365 Pro），用于快速识别实例 |
| 发布商 | 字符串 | 100 | 软件发布商（如 Microsoft） |
| 版本号 | 字符串 | 255 | 软件版本号（如 21H2），用于匹配许可证的版本要求 |
| 版本 override | 字符串 | 40 | 手动覆盖版本信息（自动发现未正确识别版本时），确保合规分析准确 |
| 发现规格 | 引用 | 32 | 发现该软件安装的模型；引用 发现映射 表数据中的 软件名称 字段值；下拉选择（引用 软件规格 对象 名称） |
| 创建时间 | 日期/时间 | 40 | 记录创建和最后更新时间戳 |

#### 3.1.4 字段说明（B. 安装详情与资产关联）

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 安装位置 | 引用 | 32 | 安装所在的硬件资产；引用台账中硬件资产的 本方案引用资产，非 CI |
| 分配给 | 引用 | 32 | 硬件资产被指派给的用户；引用台账中资产的 分配给 字段值 |
| 安装时间 | 日期/时间 | 40 | 软件安装日期，用于分析软件生命周期（识别陈旧版本） |
| 安装路径 | 字符串 | 100 | 安装路径（如 C:\Program Files\Adobe） |
| 实例密钥 | 字符串 | 1,000 | 软件实例唯一标识符，安装时自动生成（本期不考虑，样例值均为空） |
| 卸载命令 | 字符串 | 255 | 卸载命令或注册表路径（Windows 卸载标识符），支持自动化卸载；输入框 |
| ISO serial number | 字符串 | 100 | 软件 ISO 镜像的唯一序列号 |

#### 3.1.5 字段说明（C. 合规性与许可证管理）

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| Entitlement | 引用 | 32 | 关联的许可证；引用 许可证 entitlement 表 Entitlement 字段（本期丢弃不用，样例数据均为空） |
| 推断套件 | 字符串 | 32 | 该安装所属的推荐软件套件模型（如 Office 套件中的 Excel）；基于实时数据推断，合规计算时与 软件 规格 中套件定义对比 |
| 从套件中排除 | 是/否 | 10 | 选择框；表示在 reconciliation 过程中不计该安装为套件组件；勾选后需单独消耗 license |

### 3.2 页面功能与交互逻辑

#### 3.2.1 列表页（软件 Installation）

- 入口：许可证 Management 下的 软件 Installation。
- **无新增按钮**：不提供人工新增，仅展示采集/导入数据。
- 展示：软件/版本/设备/发现时间等安装明细字段。
- 操作：搜索、筛选、排序、显示设置等标准操作；编辑（修正采集数据）。

#### 3.2.2 详情页（编辑）

- 编辑软件安装记录，用于修正自动采集不准确的数据。
- **不显示删除按钮**：仅可修改，不可删除。
- 版本 override 用于手动覆盖版本；卸载命令 记录卸载路径。

### 3.3 补充说明

- 发现规格 与 ServiceNow 不同：本方案引入自建映射表（发现映射），发现规格 引用其 软件名称。
- 安装位置 引用资产（非 CI）。
- 实例密钥、Entitlement 字段本期不使用（不太可能一个软件在一台设备上安装多次；ServiceNow 中 Entitlement 已不再使用，实例数据均为空）。
- 推荐套件价值：基于实时数据得到，而 软件 规格 中定义的 suite 为静态数据，可能因合同变化未更新导致错误；合规计算时对比二者，不一致可能触发合规警告或进一步调查。

## 4. 验收标准

- 软件 Installation 可建表并导入演示数据；同维度不同时段数据以最新覆盖老数据。
- 入口位于 许可证 Management 下；列表页无新增按钮，详情页无删除按钮。
- 采集数据可被人工修正（编辑），版本 override 覆盖版本生效。
- 发现规格 正确引用 发现映射 的 软件名称；安装位置 / 分配给 正确引用硬件资产台账。
- 从套件中排除 勾选后按单独消耗 license 处理（供后续合规计算）。
- 字段与字典值符合本文定义。
