## 2. 需求分析

### 2.1 业务背景

软件发布商常将相关应用打包为套件（如 Microsoft Office 含 Word、Excel、PowerPoint、Outlook、访问）。父套件的授权许可了所有子组件，一个软件规格可同时是多个套件的组件。系统需支持维护套件父/子关系，并通过套件推理在授权与合规检查时使用最有效的套件许可，避免为子组件重复采购。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **套件级授权**：父套件授权覆盖所有子组件，减少重复许可。
- **推理优化**：套件推理在授权时选择最佳/最有效套件，降低合规成本。
- **合规继承清晰**：按订阅模式明确子组件合规检查遵循父套件还是子组件。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow SAM 的 cmdb_m2m_suite_model 多对多关系：以父/子关系维护套件，支持套件推理与合规继承。本方案对齐父/子页卡维护与 inference mandatory 规则。

### 2.3 用户故事

- 作为**规格管理员**，我希望为软件规格添加/删除子组件或父套件，以便建立套件关系。
- 作为**合规负责人**，我希望套件合规按订阅模式正确继承，以便子组件合规判定准确。

## 3. 需求设计

### 3.1 套件父/子关系维护

#### 3.1.1 涉及到的表

| 表名 [Table] | 类型 | 描述/用途 |
| --- | --- | --- |
| software suites [cmdb_m2m_suite_model] | 多对多关系表 | 存储软件套件的父套件及子组件关系 |
| 软件 规格 [cmdb_software_product_model] | 实体表 | 存储软件规格 |

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 新增 Suite Component | 在 软件规格 详情页 Suite Components 页卡 New 添加子组件 | 提交后进入 Suite 列表页，套件子级 显示 规格 的"名称+版本"；当前 规格 默认写入 套件父级；仅逐条添加（非常用操作，不提供批量） |
| 新增 Suite 父级 | 在 软件规格 详情页 Suite Parents 页卡 New 添加父套件 | 提交后 套件父级 显示 规格 的"名称+版本"；当前 规格 默认写入 套件子级；仅逐条添加 |
| inference mandatory | 复选框，勾选后合规检查使用具体规则 | 列表页 inference mandatory 列在勾选时显示"Yes" |
| Domain 设置 | 设置套件可使用的数据/权限域 | 通过数据字典维护，可为中心/部门/公司/用户组 |
| 删除 Suite Component | Suite 列表页 delete → Yes 删除子组件 | 删除后列表不再显示该记录 |
| 删除 Suite 父级 | Suite 列表页 delete → Yes 删除父套件 | 删除后列表不再显示该记录 |
| 创建/添加权限角色 | 创建 规格 与添加兼容 规格 | 角色：model_manager；sam、category_manager、asset 同样具备创建 规格 权限 |

#### 3.1.3 字段说明（software suites 关系）

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 套件父级 | 引用 | 32 | 父套件规格，显示 规格 的 名称 + 版本 |
| 套件子级 | 引用 | 32 | 子组件规格，显示 规格 的 名称 + 版本 |
| inference mandatory | 布尔 | 10 | 勾选后合规检查使用具体规则；列表勾选显示"Yes" |
| Domain | Choice | 40 | 套件可使用的数据/权限域，字典维护（中心/部门/公司/用户组等） |

#### 3.1.4 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| inference mandatory | 勾选/ 空（未勾选） | 勾选后合规检查使用具体规则；列表页显示 Yes |
| Domain | 中心 / 部门 / 公司 / 用户组 等 | 数据/权限域范围，字典维护 |

### 3.2 套件推理与合规继承

#### 3.2.1 功能描述

| 场景 | 合规继承规则 |
| --- | --- |
| 套件推理 | 确定软件是否属于套件，并在授权时推断使用最佳/最有效的套件 |
| 父套件订阅、子组件非订阅 | 子组件合规检查遵循父套件 |
| 仅子组件订阅、父套件非订阅 | 子组件合规检查遵循子组件 |
| 父套件与子组件均订阅 | 子组件合规检查遵循父套件 |
| 套件授权关系 | 套件组件使用套件许可一起授权，父套件授权即许可所有套件组件；一个软件规格可作为多个套件的组件 |

### 3.3 页面功能与交互逻辑

- **入口**：software models 列表页点击某记录名称链接进入 规格 详情页。
- **Suite Components 页卡**：New 添加子组件（套件子级 下拉显示所有软件 规格 的 名称/版本），逐条添加；列表展示 套件子级、inference mandatory；delete → Yes 删除。
- **Suite Parents 页卡**：New 添加父套件（套件父级 下拉显示所有软件 规格 的 名称/版本），逐条添加；列表展示 套件父级、inference mandatory；delete → Yes 删除。
- **Suite 列表页**：inference mandatory 勾选显示"Yes"；支持翻译（参考翻译规范）。

## 4. 验收标准

- 软件规格详情页可在 Suite Components / Suite Parents 页卡逐条新增/删除父子关系，套件子级/parent 显示 名称+版本。
- inference mandatory 勾选后列表显示"Yes"，合规检查使用具体规则；Domain 可通过字典维护。
- 套件合规继承按订阅模式（父订阅/子非订阅、仅子订阅、均订阅）三种规则正确判定子组件合规遵循对象。
- 数据存储于 cmdb_m2m_suite_model 多对多关系表，字段符合本文定义。
