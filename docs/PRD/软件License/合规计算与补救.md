## 2. 需求分析

### 2.1 业务背景

企业采购的软件许可（许可证）与实际安装/使用/客户端访问存在偏差，可能超装（合规风险、面临厂商审计罚款）或过度采购（资金浪费）。系统需按设定频次自动或手动运行合规计算，比对实际消耗与台账有效期实例的授权量，识别超装与不合规数据；将结果以报表、发布商/Product/规格 维度多层钻取展示；并提供补救措施（采购、授权分配、卸载、回收）形成闭环。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **合规风险可视**：量化超装数量、比例、金额，规避厂商审计罚款。
- **成本优化**：识别过度许可（超量授权）与超额使用（True-up），支撑采购决策。
- **多维钻取**：发布商 → Product → 规格 层层下钻定位不合规源头。
- **闭环补救**：采购权利、创建授权、移除未授权安装、回收，操作后重算验证合规。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow SAM 的 Reconciliation 与 发布商/Product/规格 合规下钻、Remediation options（采购 rights / Create allocations / Remove unlicensed installs / Reclaim），并以 True-up 成本、超量授权 Amount 作为财务参考指标。本方案沿用同类口径并落地字段与公式。

### 2.3 用户故事

- 作为**软件资产管理员**，我希望系统每日自动计算安装合规并标记超装，以便及时处置。
- 作为**采购/财务**，我希望按 发布商 查看 True-up 成本 与 超量授权 Amount，以便决定采买或止损。
- 作为**合规负责人**，我希望在 规格 层看到补救选项并一键发起流程，以便闭环处置不合规。

## 3. 需求设计

### 3.1 软件安装合规计算（合规状态 calculate of 软件 installation）

#### 3.1.1 涉及到的表

- `software_installation`（软件安装记录，实际消耗数据源）
- `software_license`（软件许可实例，含 rights / 可用授权数 / 结束日期）
- `cmdb_software_product_model`（软件规格，含 license metric / license type / metric attribute）
- `calculate_task`（合规计算任务表）
- `calculate_result`（合规计算结果表）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 定时计算 | 按采集频次设定定时任务 | 与第三方采集频次一致（如 SCCM 每日采集一次，ITAM 每日 00:01 计算一次） |
| 手动触发 | software licenses 的 More 下增加"合规状态 calculate" | 手动发起当前规格的合规计算 |
| 计算安装需要权限数 | 依 license metric + license type 计算每台设备/用户所需 rights | 例：Device 授权且按 CPU 核数计算，1 台 4 核设备需 4 个 CPU 核数取自 CMDB cpu_core_count |
| 统计需要 许可证 总量 | 依授权方式统计独立设备/用户/并集去重数量 × 每单位所需 rights | b1 按设备：独立设备数 × 每设备 rights；b2 按用户：独立用户数 × 每用户 rights；b3 用户/设备：用户与设备并集去重数 × 每单位 rights |
| 统计台账权限总量 x | 取 软件规格 关联且处于有效期的所有实例的 rights 之和 | 有效期由 结束日期 确定；结束日期 取实例关联合同页 日期 removed 值 |
| 超装判定 | 需要量 b 与台账有效期 rights 总量 x 比较 | 若 b ≤ x 且满足 metric attribute 则合规，否则不合规 |
| 超装数量与标记 | 计算超装 rights 与超装记录数 | 超量安装授权数 = |b − x|；以安装记录 创建时间 时间为准，最近的设备/用户标记超装，标记记录数 = 上取整（超量安装授权数 ÷ 每设备/用户所需 rights）；不符合 metric attribute 则标记对应记录不合规 |
| 台账授权比对与自动维护 | 实际消耗去重后与实例 user/device entitlements 比对 | 未超装时系统自动为不合规数据在有效期实例中增授权（按最早到期优先消耗）/删授权，保持台账正确；超装但库存有余量时改由人工手动为超装设备加授权 |
| 记录剩余授权 | software license 增加 可用授权数 | 可用授权数 = 实例 rights − consumed_consumed_rights 为已分配 rights |

#### 3.1.3 用户/设备（用户/Device）覆盖模式计算口径

厂商授权模式为 user/device 模式时，采用覆盖（非叠加）模式，所需权限数 = Max(user, device)。示例：用户数 100、设备数 80，总授权仅需 100 而非 180。

| 分支 | 计算规则 |
| --- | --- |
| 取采集数据 | 取 Max(用户, Device) |
| 用户 ≥ Device | 采集 用户 对比台账 user；删除/插入时 可用授权数 = 实例 rights − 台账 user, 台账 device；超装则 可用授权数 不变、unlicensed user 标 True、未授权用户 count +1 |
| 用户 < Device | 采集 Device 对比台账 device；删除/插入时 可用授权数 = 实例 rights − 台账 user, 台账 device；超装则 可用授权数 不变、unlicensed device 标 True、未授权设备 count +1 |

### 3.5 合规补救措施（Remediation）

#### 3.5.1 功能描述

补救以 发布商 → Product → 规格 逐层下钻，规格 层提供补救选项（Remediation Options）。除 部门 维度外，公司、成本中心 同样支持合规性与补救（页面与补救与 部门 类同）。

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 安装补救-下钻 | 发布商 → Product → 规格 逐层展示核心指标 | 各层显示 合计 Spend、True-up 成本、超量授权 Amount、状态；Product 层显示 Product Results 页卡 |
| 安装补救-规格 选项 | 规格 层显示 Remediation Options 页卡 | 采购 授权数 进入采购订单流程；Create Allocations 进入 license 申请流程；Remove Unlicensed Installs 进入卸载申请流程（复用回收流程） |
| 带参补救 | 勾选 Unlicensed Installs 列表项后再点补救 | 可带参数给到对应流程 |
| 使用补救 | 规格 层显示 Removal Candidates、Remediation options | 显示 软件 product、发布商、硬件 asset、用户、授权数 to reclaim；点击 Reclaim 进入回收权限流程 |
| 访问补救 | 按 部门/公司/成本中心 下钻 | 规格 层补救：采购 授权数、Create Allocations、Remove Unlicensed Installs；显示 Unlicensed Devices、Unlicensed Users 页卡；勾选后带参进入流程 |
| 补救后重算 | 补救完成后更新实例与 可用授权数，重跑合规 | 通过 class 触发器实现实例创建与 可用授权数 更新；重新 Run reconciliation 后对应 发布商 合规重算并显示最新结果 |

#### 3.5.2 字段字典值说明（补救选项与状态）

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 安装/访问 | 采购 授权数 / Create Allocations / Remove Unlicensed Installs | 采购权利 / 创建授权分配 / 移除未授权安装 |
| 使用 | Reclaim | 回收权限 |
| product/publisher 合规 | 合规 / 不合规 | 是否合规（仅考虑超装） |
| 补救维度 | 部门 / 公司 / 成本中心 | 三个维度均支持合规性与补救 |

### 3.6 页面功能与交互逻辑

- **合规任务页（Run reconciliation）**：列表展示历史任务（TaskID/Taskname/状态/类型/Progress）；发起任务可选 默认 All 多选、合规类别（默认全选）；取消当前系统旧合规检查入口。
- **合规报告页**：任务级 查看 result 进入饼图详情（合规/不合规、超装、metric attribute），点击饼图下钻列表页；Overview 展示近半年趋势。
- **发布商 合规页**：卡片展示 发布商/合规状态/True-up 成本/超量授权 Amount/合计 Spend；A→Z 排序；点击下钻 Product 列表（Last reconciled 可见，Product 可点击）。
- **补救页**：发布商→Product→规格 下钻，规格 层展示 Remediation Options/Removal Candidates 并发起对应流程；补救后重算刷新。

## 4. 验收标准

- 安装合规计算按频次自动执行并支持手动触发，超装判定（b 与 x 比较）、超装记录标记（上取整）、用户/Device 覆盖模式（Max）、metric attribute 校验均符合本文口径。
- 台账权限总量 x 仅统计有效期内实例（结束日期 取合同 日期 removed）；可用授权数 = rights − 已消耗授权数。
- 使用合规按四维度去重、回收规则（total usage time / last used date）比对，命中写入 `samp_sw_reclamation_candidate` 并计算 授权数 to reclaim / 潜在节省。
- 合规报告饼图与 Overview 趋势（三类 费率 Trend）展示正确并可下钻。
- 发布商 合规的 True-up 成本、超量授权 Amount、合计 Spend 计算与两位小数精度、$ 换算、A→Z 排序、编号 编号规则（PR+7 位）符合定义。
- 补救 发布商→Product→规格 下钻与 采购 授权数/Create Allocations/Remove Unlicensed Installs/Reclaim 流程可发起，补救后 可用授权数 更新并重算刷新；部门/公司/成本中心 三维度均可用。
