## 2. 需求分析

### 2.1 业务背景

回收规则汇总一段时间内的使用情况，并指定在软件被标记为回收之前必须使用的最少小时数或软件单元的最晚使用日期。通过了解哪些权利已分配但使用频率不高、最近使用不够频繁或根本没有使用，企业可以避免为产品购买更多软件权利。回收规则会回收软件权利，以便释放这些权利并将其分配到其他地方。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **成本节约**：识别闲置/低频使用的软件权利并回收，避免重复采购。
- **权利复用**：释放的权利可重新分配到其他地方，提升利用率。
- **自动化回收**：规则生效后自动生成回收清单，配合通知与宽限期实现自动/手动回收。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow：回收规则按总使用时长（合计 Usage 时间）或最近使用日期（Last Used 日期）判定回收候选；支持通知用户并设置自动回收宽限期；规则关联到软件产品，后续父组件（如 Microsoft 365）设定回收规则可同步应用到子软件。

### 2.3 用户故事

- 作为**软件资产管理员**，我希望配置基于总使用时长或最近使用日期的回收规则，以便识别闲置软件权利。
- 作为**软件资产管理员**，我希望规则生效后自动生成回收清单并通知用户，以便在宽限期后自动回收权利。
- 作为**软件资产管理员**，我希望将回收规则关联到指定软件产品，以便按产品维度精准回收。

## 3. 需求设计

### 3.1 回收规则新增/编辑

#### 3.1.1 涉及到的表

- `reclamation_rule`（回收规则表）
- `software_model`（软件规格，软件 install condition 引用其字段）
- `sys_user_group`（分配组，DOUC 用户组）
- `software_product`（软件产品，规则关联）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 新增回收规则 | 录入规则字段并保存 | 校验必填项，不通过提示 `The following mandatory fields are not filled in: xxx、xxx...`；点击 save 在列表页生成一条记录 |
| 取消 | 返回列表页 | cancel 直接返回列表页 |
| 编辑限制 | 编辑已有数据时 适用于 字段置灰不可编辑 | — |
| 条件字段联动 | 依据 回收类型 / 通知用户 控制字段显隐 | 见 3.1.4 字段联动规则 |

#### 3.1.3 字段说明

| 字段名称 | 翻译 | 是否必填 | 字段类型 | 业务/逻辑说明 |
| --- | --- | --- | --- | --- |
| 名称 | 名称 | 是 | 文本 | 定义规则名称 |
| 适用于 | 适用于 | 是 | 下拉单选 | 回收规则适配的软件方式；选项：安装时间 软件 |
| 回收类型 | 回收类型 | 是 | 下拉单选 | 回收类型判断方式；选项：合计 Usage 时间、Last Used 日期 |
| Create reclamation candidate | 创建回收候选 | 否（默认开启） | 开关 | 生效后是否生成回收清单；开启则生成 Reclamation candidates，关闭则不生成 |
| Include no activity | 不包括任何活动 | 否（默认关闭） | 开关 | 开启后，安装了软件但使用记录为 0 的软件也纳入回收清单 |
| 分配组 | 分配组 | 是 | 下拉搜索单选 | 生效后具体业务执行组；下拉数据为 DOUC 的用户组 |
| 通知用户 | 通知用户 | 否（默认关闭） | 开关 | 是否通过渠道通知软件回收的用户 |
| 天 before auto-reclamation | 自动回收开始时间 | 条件必填 | 正整数 | 用户收到通知后回复时间期限，到达后默认开始回收；仅 通知用户 开启时显示且必填 |
| Aggregate usage by | 总计使用情况 | 是（条件） | 下拉单选 | 计算软件使用时间的时间段；选项：Last 月份、Last Two 月、Last Three 月、Last Six 月；仅 回收类型=合计 Usage 时间 时展示 |
| 合计 hours used | 总使用时长 | 是（条件） | 整数 | 在使用时间段内统计的使用时长；仅 回收类型=合计 Usage 时间 时展示 |
| 最后使用时间 before | 上次使用时间 | 是（条件） | 下拉单选 | 选项：One 月份 Ago、Two 月 Ago、Three 月 Ago、Six 月 Ago、Nine 月 Ago、One 年份 Ago；仅 回收类型=Last Used 日期 时展示 |
| 软件 install condition | 软件安装情况 | 否 | 筛选组件 | 筛选满足条件的软件资产；交互与 资产 筛选组件一致，支持且/与/或组合；第一个下拉框为 软件 规格 中所有字段数据 |

#### 3.1.4 字段字典值与联动规则

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 适用于 | 安装时间 软件 | 适用软件方式 |
| 回收类型 | 合计 Usage 时间 / Last Used 日期 | 回收类型 |
| Aggregate usage by | Last 月份 / Last Two 月 / Last Three 月 / Last Six 月 | 使用时间段 |
| 最后使用时间 before | One 月份 Ago / Two 月 Ago / Three 月 Ago / Six 月 Ago / Nine 月 Ago / One 年份 Ago | 上次使用时间点 |

**字段联动规则：**

- 通知用户 开启 → 显示并必填 天 before auto-reclamation；关闭 → 不显示。
- 回收类型 = 合计 Usage 时间 → 显示 Aggregate usage by、合计 hours used。
- 回收类型 = Last Used 日期 → 显示 最后使用时间 before。

#### 3.3.4 穿梭框逻辑说明

- 左侧穿梭框展示 软件 Product 中所有名称（不含右侧已选内容）。
- 单次仅能选中一个 Product，底部展示选中的 Product 信息：Product、Publish、产品类型、产品分类。
- 右侧展示已选中的 Product 名称。
- 左右侧内容可互相移动，单次仅可移动一个 Product，可多次操作。
- save：点击后在新增/编辑页下的 软件 Product 中仅展示穿梭框右侧内容。
- cancel：返回新增/编辑页。

### 3.4 其他说明与后续规划

- 后续软件也会有捆绑概念（如 Microsoft 365 下含 Word、Excel、PPT 等）；当给父组件设定回收规则后，会同步应用到子软件上。

## 4. 验收标准

- 回收规则可完成新增、编辑、删除全流程；必填校验及提示语符合定义。
- 回收类型 / 通知用户 联动的条件字段（Aggregate usage by、合计 hours used、最后使用时间 before、天 before auto-reclamation）正确显隐且必填校验生效。
- 编辑时 适用于 置灰不可编辑。
- 列表页按更新时间倒序、支持分页、按名称搜索及标准操作。
- 软件 Product 页卡穿梭框选择、Run filter 筛选、save/cancel、删除 二次确认符合定义。
- 字段与字典值符合本文定义。
