## 2. 需求分析

### 2.1 业务背景

软件合规对账的目标是**检查超装情况**：（a）将采集到的数据要消耗的总量与授权 rights 比较判定是否超装；（b）根据 许可证 Metric 判定具体是用户、设备是否超装。

**合规检查的完整步骤（本期范围界定）：**

| 步骤 | 内容 | 本期是否实现 |
| --- | --- | --- |
| 第一步 | 数据收集（第三方工具对接） | 不考虑 |
| 第二步 | 定义许可证规则（许可证 type/metric、软件规格/definition 定义） | 不考虑（基础数据见其他 PRD） |
| 第三步 | 分配采购的许可证给设备/用户 | 不考虑 |
| 第四步 | 合规性比对及缺口分析 | **本期需求** |
| 第五步 | 生成报告展示风险 | 不考虑 |
| 第六步 | 整改 | 不考虑 |

本期完成两部分：软件安装合规计算（超装判定）与软件使用合规计算（对比回收规则生成回收候选，并以视图/列表展示，视图部分不做）。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **合规风险识别**：对比采集消耗与授权总量，识别超装并标记不合规记录。
- **授权自动维护**：未超装时后端自动在台账有效期实例中增删授权，保持记录正确。
- **回收决策**：使用数据对比回收规则生成回收候选，释放闲置权利。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow：合规对账基于 许可证 Metric（用户/Device/用户+Device）与 Metric Attribute 计算需求量，与有效期内实例授权总量比较；user/device 混合模式采用覆盖模式（所需权限 = Max(user, device)，而非叠加）。

### 2.3 用户故事

- 作为**合规专员**，我希望系统每日自动计算软件安装合规性，以便及时发现超装风险。
- 作为**软件资产管理员**，我希望在软件 许可证 实例 More 下手动触发合规计算，以便按需核对。
- 作为**软件资产管理员**，我希望使用数据命中回收规则时自动生成回收候选，以便回收闲置权利。

## 3. 需求设计

### 3.1 软件安装合规计算（合规状态 calculate of 软件 installation）

#### 3.1.1 涉及到的表

- `calculate_task_table`（每次计算任务存储表）
- `calculate_result_table`（每次计算结果存储表）
- `software_installation`（软件安装数据来源）
- `software_model`（许可证 metric / 许可证 type / Metric attribute）
- `software_license`（台账实例，新增 结束日期、可用授权数 字段）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 创建定时任务 | 基于采集数据计算需要的 license 数量并与台账数量对比 | 计算频次与第三方工具采集上报频次一致（如 SCCM 每天采集一次，ITAM 每天计算一次） |
| 定时触发 | 设置定时任务每天凌晨 00:01 执行 | — |
| 手动触发 | 在软件 software licenses 对应 More 下增加 合规状态 calculate | 用户可按需手动触发 |
| 记录任务与结果 | 每次合规检查新建任务，结果放在合规结果表 | 定义 Calculate_task_table、Calculate_result_table |
| 记录剩余授权 | 在 software license 表增加 可用授权数 字段 | 可用授权数 = 实例 rights - consumed_consumed_rights 按台账授权记录计算 |

#### 3.1.3 计算方法（采集消耗 许可证 总量）

**前置条件：**

- a. 根据采集安装数据，software installation 记录了安装设备及指派对象（安装位置、分配给）。
- b. 根据 software installation 的 discovery 软件规格 找到台账中 规格，明确 许可证 metric（用户 CAL / Device CAL / 用户/Device CAL）；通过 许可证 metric 找到 Metric attribute，明确授权要求（如每设备最多安装一个实例）。
- c. 通过 规格 找到 计算实际消耗按什么算，如按 CPU 数量。
- d. 找到台账中所有关联实例，通过 b、c 得知实际消耗 license 需满足的条件及计算办法（CPU 及核数从 CMDB 获取）。

**计算安装需要的权限数（b）：**

| 授权方式 | 计算逻辑 |
| --- | --- |
| 按设备授权（b1） | 统计 software installation 中所有独立设备数量；需要的 license 总量 = 设备数量 × 每台设备需要的权限数量 |
| 按用户授权（b2） | 统计所有独立用户数量；需要的 license 总量 = 用户数量 × 每设备需要的权限数量 |
| 用户/设备授权（b3） | 统计所有独立用户数量、独立设备数量，并集去重统计；license 总量 = 统计数量 × 每用户/设备需要的权限数量 |

> 示例：按 device 授权且按 CPU 数量计算，1 台设备有 4 个 CPU，则该设备需消耗 4 个权限。

**计算台账中所有权限数（x）：**

- 找到 软件规格 关联且处于有效期中的所有实例（有效期通过 结束日期 字段确定；software license 表增加 结束日期 字段，类型 日期）。
- 计算所有实例的总体权限数量（所有实例 rights 加总）为 x。
- 结束日期 取软件 license 实例关联 tab 页中合同的 日期 removed 值。

#### 3.1.4 比较逻辑

**总量比较：**

- 1.1 以需要消耗数据 b 与所有有效期内相关实例 rights 总量 x 比较：若 `b <= x` 且满足 metric attribute 要求，则合规，否则不合规。
- 1.2 不合规判定：以安装记录 创建时间 时间为准，超装 rights 数量 `|b - x| = over_install_rights`；最近的访问设备或用户数据标记为超装，数量 = ⌈超量安装授权数 / 每设备(用户)需要的 rights 数量⌉（上取整）；若不符合 metric attribute，标记对应记录不合规（后续放 workbench 展示且可点击）。

**台账实例合规比较：**

- 2.1 实际消耗 device、user、device/user 去重，与所有台账有效期实例中对应 user entitlements、device entitlements 比较，匹配则合规，否则标记不合规。
- 2.1.1 若实际消耗总量未超装：系统自动为不合规数据在台账有效期实例中增/删授权（按有效期到达时间先后增加，马上到期的先消耗），保持台账记录正确；若超装但库存有余量，改由人工手动为超装设备添加授权。
- 2.1.2 若实际消耗总量已超装：最近的超装记录展示给用户；其余实际消耗数据继续走 2.1.1（如 10 个消耗其中超装 2 个直接展示，其余 8 个继续检查台账授权记录）。
- 2.2 记录每个实例当前剩余授权数量：software license 表增加 available_类型/长度与 rights 相同；可用授权数 = 实例 rights - 已消耗授权数。

#### 3.1.5 user/device 覆盖模式计算口径

软件厂商授权模式为 user/device 模式时，通过覆盖模式管理（所需权限 = Max(user, device)，非叠加）。例如用户数 100、设备数 80，总授权仅需 100 而非 180。

| 条件 | 处理逻辑 |
| --- | --- |
| 取采集数据 Max(用户, Device)，若 用户 >= Device | 采集 用户 对比台账 user；删除/插入 可用授权数 = 实例 台账 user, 台账 device；超装标记：可用授权数 不变、未授权用户 标记 True、未授权用户 count +1 |
| 否则（Device > 用户） | 采集 device 对比台账 device；删除/插入 可用授权数 = 实例 台账 user, 台账 device；超装标记：可用授权数 不变、未授权设备 标记 True、未授权设备 count +1 |

### 3.2 软件使用合规计算（合规状态 calculate of 软件 usage）

#### 3.2.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 使用数据去重 | 采集数据以 user+product+publisher+hardware asset 四维度 X 标识匹配的软件安装 | 不能为同一月份/年份的相同四维度记录创建重复使用信息；发现重复只能用最新采集数据更新已有数据 |
| 对比回收规则 | 软件使用数据对比回收规则，结果写入回收表 | 回收规则两种：一段时间内总使用时长（合计 Usage 时间）、最近一次使用时间（Last Used 日期） |
| 合规判定 | 合规指使用与回收规则对比不会触发回收 | 使用时长或上次使用时间不触发基于回收规则设置的回收即为合规 |
| 结果保存 | 保存计算任务与详细结果 | 定义 Software_usage_Calculate_task_table、Software_usage_compliance_result |
| 视图展示 | 整体/单 Product 合规趋势视图 | 本期不做（见 3.2.5） |

#### 3.2.3 合规计算逻辑

**合计 Usage 时间 型：** 汇总使用时长设为 N 小时。对 software usage 单条数据计算（如当前 4 月、规则设为 last two months 时，将 3 月、2 月使用时长加总并转为 hour）后对比 N 小时。

**Last Used 日期 型（举例）：** 当前时间 2025-04-23，规则设为 2 个月前（按自然月推算为 2025-02-23）；对比软件最近一次使用时间，若早于 2025-02-23（如 2025-02-20）则需回收，否则不需要。

计算逻辑：基于用户、设备对软件的使用时长或最近一次使用时间计算，若命中回收规则则写入软件回收表等待回收。进入回收表的数据由定时任务查看，若有待回收对象且回收规则选择通知用户，则通过宽限期自动向用户发送通知（本期先不做）；到达回收时间后自动/手动回收权限（流程本期不涉及）：从台账删除授权、更新 可用授权数，回收成功后通知用户并从回收表移除。

## 4. 验收标准

- 安装合规计算：定时任务每天 00:01 执行，且实例 More 下 合规状态 calculate 可手动触发；计算频次与采集频次一致。
- 按 许可证 metric（用户/Device/用户+Device）正确计算需求量 b 与台账有效期实例授权总量 x，`b<=x` 且满足 metric attribute 判合规，否则标记不合规。
- 超装数量按 `⌈|b-x| / 每设备(用户)rights⌉` 上取整；user/device 覆盖模式按 Max(user, device) 计算。
- 未超装时后端自动增删台账授权（按有效期先后）；可用授权数 = 实例 rights - 已消耗授权数 正确维护。
- Calculate_task_table / Calculate_result_table 字段与字典值符合本文定义；有一条不合规则任务整体 不合规。
- 使用合规计算：四维度 X 去重、同年月不可重复（用最新覆盖）；按 合计 Usage 时间 / Last Used 日期 正确对比回收规则并生成回收候选写入 samp_sw_reclamation_candidate。
- 回收规则 关联改为 product、列表显示 Product 名称、Create reclamation candidate 改名 启用、软件 usage 必填项调整均生效。
- 视图展示部分本期不做，符合范围界定。
