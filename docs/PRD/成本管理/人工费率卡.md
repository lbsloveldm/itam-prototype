## 2. 需求分析

### 2.1 业务背景

企业在核算服务/项目的人工成本时，需要为不同岗位或角色（如工程师、项目经理、技术支持）定义标准工时成本，以确保内部或对外服务定价的一致性，避免人为估算导致的成本偏差。人工费率卡（Labor 费率 Card）是标准化人工成本核算的基础数据，在流程节点按工时计费时被引用，直接影响费用条目金额与资产 TCO。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **标准化成本核算**：明确不同角色的工时成本，统一计价基准，提升财务数据准确性与可比性。
- **预算管理与成本控制**：基于费率卡快速估算人力成本，实时对比实际工时识别超支。
- **资源优化配置**：按任务复杂度匹配角色，平衡成本与效率，支持多项目优先级排序。
- **客户透明化计费**：对外服务时展示基于费率卡的成本拆分，支持灵活定价（折扣/溢价）。
- **合规与审计支持**：标准化流程、记录费率卡历史版本与调整依据，便于审计。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow 的 费率 card 模型：费率卡按条件匹配任务、以优先级（order）择优，并支持币种配置。本期人工费率卡对齐该模型，条件来源为 用户 表字段。

### 2.3 用户故事

- 作为**财务人员**，我希望为不同角色定义标准小时费率，以便统一核算人工成本。
- 作为**成本管理员**，我希望通过条件与优先级控制费率卡的适用范围，以便在多卡匹配时择优使用。
- 作为**运维负责人**，我希望流程按执行人的费率卡自动计费，以便真实反映任务人工成本。

## 3. 需求设计

### 3.1 设置人工费率卡

#### 3.1.1 涉及到的表

- `labor_rate_card`（人工费率卡表）
- `user`（用户表，Condition 过滤条件数据来源）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 入口 | 在配置中增加入口 TCO 配置，点击一级菜单后可见 Labor 费率 Card | 一级菜单项 TCO 配置 → Labor 费率 Card |
| 列表页 | 点击 Labor 费率 Card 进入列表页 | 展示已创建费率卡 |
| 创建费率卡 | 点击 New 进入创建 人工费率 card 页面 | 填写下述字段，编号 系统默认生成 |
| 编号 生成规则 | 费率卡唯一标识，规则为「LBRC+7 位数字」 | 点击新增时由系统默认生成 |
| 优先级匹配 | 多个费率卡匹配同一任务时，按 排序 由低到高择优 | 排序 值越小优先级越高 |
| Condition 应用范围 | 通过过滤条件精确控制费率卡应用范围 | 数据来源为 用户 表所有字段，设置页面与当前系统一致 |

#### 3.1.3 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 启用 | 是/否 | 40 | 勾选项，代表费率卡是否处于活跃状态；未勾选则不生效 |
| 编号 | 字符串 | 40 | 费率卡唯一标识，生成规则「LBRC+7 位数字」，新增时系统默认生成 |
| 名称 | 字符串 | 40 | 费率卡名称，用于描述用途或适用场景（如：高级工程师费率） |
| 费率 code | 字符串 | 40 | 根据业务场景（部门/角色/地区）对费率卡进行分类 |
| 小时费率 | 币种 | 20 | 符合条件时员工每小时工时成本（如 $75/小时）；币种可选值与当前系统相同 |
| 排序 | 整数 | 40 | 多个费率卡匹配同一任务时，按 排序 由低到高择优 |
| Condition | Conditions | 4,000 | 过滤条件，基于任务属性/员工角色/地理位置等维度定义；数据来源为 用户 表所有字段 |
| 简短描述 | 字符串 | 80 | 对该费率卡的描述补充 |

#### 3.1.4 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 启用 | 是 / 否 | True=费率卡生效；False=费率卡不生效 |
| 编号 前缀 | LBRC | 人工费率卡编号前缀，后接 7 位数字 |

### 3.2 页面功能与交互逻辑

#### 3.2.1 列表页

- 入口：TCO 配置 → Labor 费率 Card。
- 展示费率卡记录（启用、编号、名称、费率 code、小时费率、排序 等）。
- 操作：新建（New）、编辑、查看；编号 只读由系统生成。

#### 3.2.2 创建/编辑页

- 填写 名称、费率 code、小时费率、排序、Condition、简短描述；启用 勾选；编号 系统生成。
- Condition 设置页面与当前系统条件构建器一致，字段来源 用户 表。
- 小时费率 币种可选值与系统一致。

### 3.3 计费应用逻辑（与费用条目/TCO 联动）

| 需求点 | 逻辑描述 |
| --- | --- |
| 工时计费引用 | 流程节点按工时计费时，引用执行人匹配到的人工费率卡 小时费率 |
| 多卡择优 | 执行人关联的单小时费用有多条记录时，以 排序 小的为准 |
| 兜底 | 执行人未定义人工费率卡时，以任务费率卡中的 默认 rate card 为准 |
| 生效条件 | 仅 启用=True 且 Condition 命中的费率卡参与匹配 |

### 3.4 校验与约束

- 编号 全局唯一，遵循「LBRC+7 位数字」规则，系统生成只读。
- 仅 启用=True 的费率卡生效。
- 多卡匹配以 排序 由低到高择优。

## 4. 验收标准

- 可从 TCO 配置 → Labor 费率 Card 进入列表并创建费率卡，字段与字典值符合本文定义。
- 编号 按「LBRC+7 位数字」自动生成且唯一。
- Condition 条件来源 用户 表；小时费率 币种与系统一致。
- 流程按工时计费时正确引用费率卡，多卡按 排序 择优，未匹配走任务费率卡兜底。
