## 2. 需求分析

### 2.1 业务背景

企业在处理运维/服务任务时，需要对每项任务的成本进行透明化与精准核算。通过任务费率卡（Task 费率 Card）为不同任务预定义费率（固定费率或基于工时的动态费率），可清晰追踪每项任务的成本来源（人力、资源或工具费用），减少因未明确定价导致的意外支出。例如 IT 部门处理「服务器故障修复」任务时，系统可自动按工程师工时费率（如 $80/小时）或固定费率（如 $500/次）核算成本。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **成本透明化与精准核算**：预定义任务费率，明确任务成本结构，提升财务可视性。
- **避免隐性成本**：减少因未明确定价导致的意外支出（如超时服务、资源浪费）。
- **两种计费模式**：支持按实际工时（关联人工费率卡）与按固定费率两种方式。
- **兜底机制**：员工无个人费率卡时使用 默认 labor rate 保障计费不中断。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow 的任务/费率卡模型：按任务与节点匹配费率，支持固定费率与工时费率、优先级择优与币种配置。本期任务费率卡对齐该模型，节点来源为 DOSM 流程节点。

### 2.3 用户故事

- 作为**成本管理员**，我希望为每类任务/节点配置固定或工时费率，以便自动核算任务成本。
- 作为**运维负责人**，我希望员工无个人费率卡时有默认小时费率兜底，以便计费不中断。
- 作为**财务人员**，我希望多卡匹配时按优先级择优，以便计费口径唯一可控。

## 3. 需求设计

### 3.1 设置任务费率卡

#### 3.1.1 涉及到的表

- `task_rate_card`（任务费率卡表）
- `labor_rate_card`（人工费率卡表，Use time worked 时关联）
- DOSM 流程/节点接口（Taskname、Nodename 下拉来源）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 入口 | 在配置中增加入口 TCO 配置，点击一级菜单后可见 Task 费率 Card | 一级菜单项 TCO 配置 → Task 费率 Card |
| 列表页 | 点击 Task 费率 Card 进入列表页 | 展示已创建任务费率卡 |
| 创建费率卡 | 点击 New 进入创建 任务费率 card 页面 | 填写下述字段，编号 系统默认生成 |
| 编号 生成规则 | 费率卡唯一标识，规则为「TKRC+7 位数字」 | 点击新增时由系统默认生成 |
| 计费模式联动 | 勾选 Use time worked 显示 默认 labor rate；未勾选显示 任务费率 | 两字段互斥显示 |
| 节点下拉来源 | Taskname/Nodename 通过 DOSM 接口获取流程名/节点名 | Nodename 下拉仅含人工节点，不含自动化节点（DOSM 可区分） |
| 优先级匹配 | 多个费率卡匹配同一任务时，按 排序 由低到高择优 | 创建时不同记录 排序 不相同 |
| Condition 应用范围 | 通过过滤条件精确控制费率卡应用范围 | 数据来源为所选流程节点中的所有表单属性字段，设置页面与当前系统一致 |

#### 3.1.3 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 启用 | 是/否 | 40 | 勾选项，代表费率卡是否处于活跃状态；未勾选则不生效 |
| 编号 | 字符串 | 40 | 费率卡唯一标识，生成规则「TKRC+7 位数字」，新增时系统默认生成 |
| 名称 | 字符串 | 40 | 费率卡名称，用于描述用途或适用场景（如：高级工程师费率） |
| Taskname | 字符串 | 80 | 通过 DOSM 接口获取的流程名称，下拉可选 |
| Nodename | 字符串 | 80 | 通过 DOSM 接口获取的流程节点名称，关联流程名称的节点名；下拉仅含人工节点 |
| Use time worked | 是/否 | 40 | 勾选=按实际工时计算成本（关联员工人工费率卡）；未勾选=按固定费率 任务费率 计算，与工时无关 |
| 任务费率 | 币种 | 20 | 任务固定成本，支持多货币配置（如「服务器巡检」每次 $300）；币种与系统一致 |
| 默认 labor rate | 币种 | 20 | 员工未分配个人费率卡时使用的默认小时费率（兜底），仅勾选 Use time worked 时显示 |
| 排序 | 整数 | 40 | 多个费率卡匹配同一任务时，按 排序 由低到高择优；创建时不同记录 排序 不相同 |
| Condition | Conditions | 4,000 | 过滤条件，基于任务属性/员工角色/地理位置等维度定义；数据来源为所选流程节点中的所有表单属性字段 |
| 简短描述 | 字符串 | 80 | 对该费率卡的描述补充 |

#### 3.1.4 字段字典值说明

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| 启用 | 是 / 否 | True=费率卡生效；False=费率卡不生效 |
| Use time worked | True | 按实际工时计算成本，显示 默认 labor rate，关联员工人工费率卡 |
| Use time worked | False | 按固定费率 任务费率 计算，与工时无关，显示 任务费率 |
| Nodename 范围 | 仅人工节点 | 节点下拉不包含自动化节点（DOSM 可区分人工/自动化节点） |
| 编号 前缀 | TKRC | 任务费率卡编号前缀，后接 7 位数字 |

### 3.2 页面功能与交互逻辑

#### 3.2.1 列表页

- 入口：TCO 配置 → Task 费率 Card。
- 展示费率卡记录（启用、编号、名称、Taskname、Nodename、Use time worked、排序 等）。
- 操作：新建（New）、编辑、查看；编号 只读由系统生成。

#### 3.2.2 创建/编辑页

- 选择 Taskname、DOSM 提供，Nodename 仅人工节点。
- 勾选 Use time worked：显示 工时计费兜底；取消勾选：显示 固定费率。
- 填写 不同记录不相同、来源所选节点表单属性字段、简短描述。

### 3.3 计费应用逻辑（与费用条目/TCO 联动）

| 需求点 | 逻辑描述 |
| --- | --- |
| 工时计费 | 勾选 Use time worked：按员工工时 × 人工费率卡 小时费率 计算；员工无个人费率卡时用 默认 labor rate 兜底 |
| 固定费率计费 | 未勾选 Use time worked：按 任务费率 固定值计算，与工时无关 |
| 固定费用多卡择优 | 关联到的固定节点费用有多条时，以任务定义中 排序 小的为准 |
| 生效条件 | 仅 启用=True 且 Condition 命中、Taskname/Nodename 匹配的费率卡参与计算 |

### 3.4 校验与约束

- 编号 全局唯一，遵循「TKRC+7 位数字」规则，系统生成只读。
- 同一批次不同费率卡的 排序 值不得相同。
- Nodename 仅允许人工节点。
- Use time worked 与固定费率互斥：勾选显示 默认 labor rate，未勾选显示 任务费率。

## 4. 验收标准

- 可从 TCO 配置 → Task 费率 Card 进入列表并创建费率卡，字段与字典值符合本文定义。
- 编号 按「TKRC+7 位数字」自动生成且唯一；不同记录 排序 不相同。
- Taskname/Nodename 来源 DOSM，Nodename 仅人工节点；勾选 Use time worked 显示 默认 labor rate，否则显示 任务费率。
- 计费时按工时/固定费率正确核算，员工无个人费率卡走 默认 labor rate 兜底，多卡按 排序 择优。
