## 2. 需求分析

### 2.1 业务背景

传统资产管理只关注「采购成本」，无法反映资产在全生命周期中的真实开销（部署、运营、维护、停机、退役等）。企业需要突破采购成本的局限，通过全面归集资产各阶段的直接与间接成本，量化资产的总拥有成本（TCO），支持「低价采购、高价维护」陷阱的识别与替换决策。系统基于 规格 层设置的基准成本/阈值，结合资产实际发生的费用条目（含流程节点自动产生的费用），计算出每个资产的 资产 TCO，并与基准比对给出预警状态，最终在洞察看板中多维度呈现。

### 2.2 需求价值

#### 2.2.1 模块价值点

- **全生命周期成本可视**：从采购、部署、运营、维护到退役，逐阶段归集成本，覆盖显性与隐性成本。
- **基准对标与预警**：以 规格 的基准成本/阈值为对标线，自动判定资产 TCO 是否 Reached / Approaching / 未达到，触发成本优化。
- **父子资产成本穿透**：机柜等父资产的 TCO 自动包含其子资产（服务器、交换机、SSD 等）成本，支持层级化成本核算。
- **流程费用自动归集**：资产涉及的流程节点完成后自动生成费用条目并挂载到资产，减少人工登记。
- **决策支持**：识别高 TCO 型号、按成本中心/类别分布分析，辅助资本规划与替换决策。

#### 2.2.2 调研结论及竞品分析

参考 ServiceNow HAM 的 资产 Analytics 查看：提供「达到/接近 TCO 基准成本」概要数字与饼图、按成本中心分布、平均 TCO 最高的 Top 10 型号、按类别达到基准、资产费用分配（人工/发货/采购）、每月费用分布、资本规划（生命周期>60 天未停用）等报表。本期 TCO 看板对齐该套报表口径，报表明细见 3.5。

### 2.3 用户故事

- 作为**财务人员**，我希望资产自动归集其全生命周期的所有费用条目并算出 资产 TCO，以便进行资产价值核算与预算复盘。
- 作为**资产管理员**，我希望在硬件 规格 上设置基准成本与阈值，系统自动判定资产 TCO 状态，以便及时发现成本超标的资产。
- 作为**IT 经理**，我希望看到平均 TCO 最高的 Top 10 型号与按成本中心的 TCO 分布，以便优化采购与替换策略。

## 3. 需求设计

### 3.1 硬件 规格 设置 TCO 基准成本与阈值

#### 3.1.1 涉及到的表

- `规格`（规格模型表，硬件 规格 新增 TCO 基准字段）
- `asset`（资产主表，展示/计算 TCO 字段）

#### 3.1.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 规格 设置基准字段 | 在 hardware 规格 创建页新增 TCO Benchmark 成本、TCO Benchmark 阈值 两个字段 | 入口：hardware 规格 点击创建 规格 后可见两字段 |
| 阈值自动填充 | 用户输入 benchmark cost 后，benchmark threshold 自动填充 | 默认按 benchmark cost 的 75% 自动填充，支持人工修改 |

#### 3.1.3 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| TCO Benchmark 成本 | 币种 | 20 | 基准成本：行业同类设备的合理成本区间值（含隐性成本） |
| TCO Benchmark 阈值 | 币种 | 20 | 基准阈值：企业设定的 TCO 警戒线，默认 = benchmark cost × 75%，可人工修改；超过需触发成本优化流程 |

### 3.2 硬件资产展示 TCO 相关字段

#### 3.2.1 涉及到的表

- `asset`（资产主表，Financial 模块）
- `规格`（提供基准成本/阈值填充值）
- `expense_line`（费用条目表，资产 TCO 计算来源）

#### 3.2.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 展示 TCO 字段 | 在资产 Financial 模块增加 4 个字段：资产 TCO、TCO Benchmark 成本、TCO Benchmark 阈值、TCO Benchmark 状态 | 展示位置为资产详情 Financials 分组 |
| 资产 TCO 取值 | 由系统按 3.3 规则计算得到 | 汇总本资产及子资产的 父级 为空金额 |
| 基准字段填充 | Benchmark 成本 / 阈值 由对应 规格 字段值直接填充 | 取所属 规格 的 TCO Benchmark 成本 / 阈值 |
| 状态判定 | TCO Benchmark 状态 按 资产 TCO 与基准比较自动判定 | 见 3.2.4 状态判定规则 |

#### 3.2.3 字段说明

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| 资产 TCO | 币种 | 20 | 系统计算的资产实际总拥有成本 |
| TCO Benchmark 成本 | 币种 | 20 | 由对应 规格 的基准成本字段直接填充 |
| TCO Benchmark 阈值 | 币种 | 20 | 由对应 规格 的基准阈值字段直接填充 |
| TCO Benchmark 状态 | VARCHAR | 40 | 字典值：Reached / Approaching / 未达到，反映资产 TCO 是否需采取成本优化措施 |

#### 3.2.4 字段字典值说明（TCO Benchmark 状态 状态判定）

| 字段名 | 字典值 | 说明 |
| --- | --- | --- |
| TCO Benchmark 状态 | Reached | 当 `资产 TCO >= TCO Benchmark Cost`，表示已达到基准成本，需采取成本优化措施 |
| TCO Benchmark 状态 | Approaching | 当 `TCO Benchmark 阈值 <= 资产 TCO < TCO Benchmark Cost`，表示接近基准，需关注 |
| TCO Benchmark 状态 | 未达到 | 当 `资产 TCO < TCO Benchmark 阈值`，表示成本正常 |

### 3.3 资产 TCO 计算规则

#### 3.3.1 涉及到的表

- `asset`（资产主表，含父子层级 父级 引用）
- `expense_line`（费用条目表，含 Amount、父级、类型 字段）

#### 3.3.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 单资产成本 | 汇总与本资产关联、且 Expense line 中 父级 为空的 Amount | 得到资产的运营及购买成本 |
| 父子穿透 | 资产成本包含其所有子资产的费用条目 | 例如机柜 资产 TCO 包含服务器、交换机、SSD 硬盘成本 |
| 计算公式 | 资产 TCO = 本资产 父级 为空 Amount 之和 + 子资产 父级 为空 Amount 之和 | 逐层向下汇总 |
| One-time/Recurring 汇总 | 父资产 One-time = 父资产 cost + 所有子资产 cost；父资产 Recurring = 父资产 Recurring + 所有子资产 Recurring | 在 资产 TCO 柱状图中以不同颜色区分 One-time 与 Recurring |

#### 3.3.3 计算完整举例

> 场景：asset A 下包含子资产 a1、a2、a3，a1 下包含子资产 a12。购买资产对应 cost 分别为 cost A、cost a1、cost a2、cost a3、cost a12。流程分别执行过：将 A 从某库房移动到另一库房花费 200¥；将 a1 处置卖出 100¥。
> - asset A 的 Expense line 有两条：cost A、移动任务 +200¥；
> - asset a1 的 Expense line 有两条：cost a1、处置任务 -100¥；
> - 以上记录的 父级 均为空。
> - **asset A 的 资产 TCO = cost A + 200 + cost a1 - 100 + cost a3 + cost a12 + cost a2**

### 3.4 流程节点 Expense line 自动生成规则

#### 3.4.1 涉及到的表

- `expense_line`（费用条目表）
- `labor_rate_card`（人工费率卡表，工时计费引用）
- `task_rate_card`（任务费率卡表，固定/兜底费率引用）
- `asset`（资产主表，费用挂载对象）

#### 3.4.2 功能描述

| 需求点 | 需求描述 | 逻辑描述 |
| --- | --- | --- |
| 节点费用生成 | 资产涉及的流程节点被完成时，计算该节点产生的费用并挂在对应资产下 | 触发条件：DOSM 流程节点完成 |
| 多资产分摊 | 若一个节点费用涉及多个资产 | 按「总费用 / 资产数量」得到单个资产的费用 |
| 人工费率优先级 | 计算费用时若执行人关联的单小时费用有多条记录 | 以人工费率卡定义中 排序 小的为准 |
| 人工费率兜底 | 若执行人未定义人工费率卡 | 以任务节点费率卡中的 默认 rate card 为准（兜底） |
| 固定节点费用优先级 | 计算费用时若关联到的固定节点费用有多条记录 | 以任务定义中 排序 小的为准 |
| 时长取整 | 获取 DOSM 提供的时长后，采用向上取整计算消耗小时数 | 例如 3.12 小时向上取整为 4 小时 |
| 类型 归类 | 由 cost 生成的费用条目 类型=One-time；其他类型费用 类型=Recurring | 在 资产 TCO 柱状图中用不同颜色表征 |
| Task 字段展示与跳转 | 自动生成费用条目时，Task 字段展示「任务名称+节点名称」，并保存 DOSM 同步的工单 ID | Task 可点击，点击后进入对应流程任务；DOSM 当前仅能跳转至工单且显示当前节点 |

#### 3.4.3 字段说明（自动生成的 Expense line 关键字段）

| 字段名 | 数据类型 | 长度 | 备注说明 |
| --- | --- | --- | --- |
| Amount | 币种 | 20 | 节点产生的费用金额，多资产时为总费用/资产数量 |
| 类型 | VARCHAR | 40 | One-time / Recurring；由 cost 生成的为 One-time |
| Task | VARCHAR | 200 | 展示「任务名称+节点名称」，可点击跳转至 DOSM 工单 |
| DOSM 工单 ID | VARCHAR | 40 | DOSM 同步的工单唯一标识，用于跳转与追溯 |
| 父级 | VARCHAR | 32 | 费用条目父级引用，为空的条目参与 资产 TCO 汇总 |

### 3.6 页面功能与交互逻辑

#### 3.6.1 硬件 规格 创建页

- Financial/TCO 分组新增 TCO Benchmark 成本、TCO Benchmark 阈值 两字段；输入 benchmark cost 后 threshold 自动按 75% 填充且可修改。

#### 3.6.2 资产详情页（Financials 模块）

- 展示 资产 TCO、TCO Benchmark 成本、TCO Benchmark 阈值、TCO Benchmark 状态 四字段；后三者来源于 规格 / 计算，均为只读。
- 资产 TCO 柱状图区分 One-time / Recurring 两种颜色；父资产聚合展示子资产成本。
- Expense line 列表中自动生成的费用条目 Task 字段可点击跳转 DOSM 工单。

#### 3.6.3 TCO 看板页

- 呈现 3.5 报表清单；仅硬件的报表在非硬件视图下隐藏或置空。

### 3.7 校验与约束

- TCO Benchmark 状态 严格按 3.2.4 阈值区间判定，边界值归属遵循「>= 基准成本 → Reached」「>= 阈值且 < 基准成本 → Approaching」「< 阈值 → 未达到」。
- 资产 TCO 仅汇总 父级 为空的 Expense line，避免重复计算子条目。
- 流程节点费用时长一律向上取整；多资产按数量均摊。

## 4. 验收标准

- 硬件 规格 可设置基准成本与阈值，阈值默认按 75% 自动填充并可修改。
- 资产 Financials 展示 4 个 TCO 字段，基准字段由 规格 填充，状态按阈值区间准确判定。
- 资产 TCO 按「本资产 + 子资产 父级 为空 Expense line 之和」计算，父子穿透正确（符合 3.3.3 举例结果）。
- 流程节点完成后自动生成 Expense line，费率优先级/兜底/时长取整/多资产均摊逻辑正确，Task 可跳转 DOSM。
- TCO 看板报表口径与 3.5 清单一致，仅硬件报表适用范围正确。
